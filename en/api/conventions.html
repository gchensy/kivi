Conventions#

Every public function of kivi follows the rules on this page. The module pages and the guides take them for granted, and the docstrings mention only where a function departs from them or adds to them.

Imports#

kivi has no top-level imports. Import each function from its module, as in from kivi.woe import woe_table; each module has its own page in this reference.

Arguments#

  • The data come first and the target follows them, as in woe_table(groups, target), roc_auc(score, target), stepwise(X, target) and fit_spec(frame, target). A function with several data arguments takes all of them before the target, as swap_set(current, new, target) does, and a predicted probability comes after the target, as in calibration_table(groups, target, probability). scikit-learn’s metrics take the target first, so check the order when porting code from them.

  • A predicted probability of an event, such as a PD, is always called probability, as in brier_score(probability, target), calibration_table(groups, target, probability) and expected_loss(probability, lgd, ead). What a score is depends on the module; see Targets, scores and probabilities. A second probability is named after its meaning, as origination_probability in significant_increase().

  • An option with the same meaning has the same name in every module, such as bins, special, smoothing, unseen and weights. level is the confidence level of an interval, a number strictly between 0 and 1 that defaults to 0.95, as in roc_auc_interval().

  • A reference that could be read in two ways has one argument for each. The functions of kivi.monitoring take either reference_period, a label of the period argument, or a reference sample in reference_score or reference_groups, and raise unless exactly one is given.

  • The data, and the fitted results that a function applies, such as the edges of cut() or the table of woe_transform(), are positional arguments. Every option after them is keyword-only. The number of bins of bin_edges() is the one option that can also be passed by position:

>>> from kivi.binning import bin_edges
>>> bin_edges([1, 2, 3, 4], 2)
array([-inf,  2.5,  inf])
>>> bin_edges([1, 2, 3, 4], 2, method="uniform")
array([-inf,  2.5,  inf])
>>> bin_edges([1, 2, 3, 4], 2, "uniform")
Traceback (most recent call last):
    ...
TypeError: bin_edges() takes from 1 to 2 positional arguments but 3 were given

Inputs and results#

  • A one-dimensional input is array_like: a list, a NumPy array or a pandas Series. A function that works on several columns at once, such as stepwise() or fit_spec(), takes a DataFrame.

  • A result with one value per input value is shaped like the input. A Series gives a Series with the same index and name, other array_like input gives a NumPy array, and a single number gives a float. cut() and assign_grades() return groups, so for input other than a Series they return a pandas.Categorical:

>>> import pandas as pd
>>> from kivi.calibration import prior_correction
>>> rates = dict(sample_rate=0.5, population_rate=0.02)
>>> prior_correction([0.5, 0.2], **rates).round(4)
array([0.02  , 0.0051])
>>> prior_correction(pd.Series([0.5, 0.2], index=["a", "b"], name="pd"), **rates).round(4)
a    0.0200
b    0.0051
Name: pd, dtype: float64
>>> round(prior_correction(0.5, **rates), 4)
0.02

  • Series that describe the same observations, such as the data, the target, the probabilities and the weights, must have identical indices; they are not aligned. Any other combination of these inputs is matched by position. Inputs that describe other observations, such as the two samples of psi_table() or the rejected applicants of parceling(), can have any index.

  • Tables are DataFrames. A table with one row per group is indexed by the group labels, in an index named bin. A total is the sum of a column, such as woe_table(groups, target)["iv"].sum().

  • Functions do not modify their inputs. Random draws come from a local generator seeded by rng, so they never change NumPy’s global state, and the same seed gives the same result.

Targets, scores and probabilities#

  • A target is 1 for an event, such as a default, and 0 for a non-event. Any other label, and a missing label, raises an error. swap_set() and monitoring_table() are the exceptions: they read a missing label as an outcome that is not known, such as that of a declined applicant or of a loan whose outcome window has not ended.

  • In kivi.metrics, kivi.monitoring and kivi.strategy, a score rises with the event probability. Pass a PD as it is, and negate scorecard points, which fall as the risk rises. A cut-off of kivi.strategy approves the scores at or below it.

  • In kivi.scorecard, a score is scorecard points, which fall as the risk rises: score_to_pd() gives a lower PD for a higher score.

  • platt_fit() accepts a score in either direction and fits a negative slope to one that falls as the risk rises. isotonic_fit() assumes a rising score unless increasing=False.

  • True and False count as 1 and 0 in targets, scores and probabilities. Weights, LGDs, exposures and losses reject them, and so do most numeric options, such as bins, max_bins, factor and the cut-offs. Two inputs reject them because a boolean there is more likely a mistake: the reference_score of monitoring_table(), which would usually be a row mask, and the matrix of transition_pd():

>>> import numpy as np
>>> from kivi.metrics import roc_auc
>>> roc_auc([0.1, 0.9, 0.4], [False, True, True])
1.0
>>> from kivi.strategy import expected_loss
>>> expected_loss(np.array([0.1, 0.2]), np.array([True, False]), 100.0)
Traceback (most recent call last):
    ...
ValueError: lgd must be real and numeric, got dtype bool

Groups and missing values#

The functions that count groups, such as woe_table(), psi_table() and calibration_table(), take the labels as they are: the intervals of pandas.cut or kivi.binning.cut(), strings, numbers or categories.

  • Missing values form a group of their own.

  • Only observed groups appear. Unused categories are left out, and so are the groups whose weights sum to zero. The period tables of kivi.monitoring are the exception: they keep a row for every category of a categorical period, so that the rows of all reports line up.

  • Categorical groups, including the intervals of pandas.cut, follow the order of their categories, with the missing group last. Other labels follow the order in which they first appear.

>>> from kivi.woe import woe_table
>>> woe_table(["b", "a", None, "a"], [1, 0, 1, 0])[["non_event", "event"]]
     non_event  event
bin
b            0      1
a            2      0
NaN          0      1

Categories are matched to a fitted table or grouping by equality, and a category that it does not know raises an error unless unseen says how to treat it. woe_transform(), group_categories() and csi_table() share this rule, the last through unseen_points. reason_codes() matches points rather than categories, and its unseen_points exempts the points that woe_transform gave unseen groups.

The functions that count, rank or fit, such as roc_auc(), calibration_table(), cutoff_table() and platt_fit(), raise an error for a missing score or probability instead, so decide how missing values are scored before passing them in. The functions that convert each value on its own, such as pd_to_score(), platt_predict() and expected_loss(), return NaN for a missing value, and assign_grades() returns a missing grade. The staging functions of kivi.lifetime work value by value but raise for a missing value, because a missing PD or number of days past due must not decide a stage, and the functions of kivi.monitoring raise for a missing period.

Sample weights#

Most functions that count observations or fit a model take weights: one finite, non-negative number per observation, matched to the data like the target. psi_table() and csi_table() take one set for each sample, reference_weights and current_weights.

  • Counts become sums of weights, and observations with zero weight are left out. Integer weights therefore give the same counts as repeating each row that many times.

  • Weighted quantiles use the inverted CDF, so every interior quantile edge is an observed value, while unweighted quantiles interpolate between observations. Weighted edges therefore agree with repeated rows only where no interpolation is needed, and weights of 1 do not give the same edges as no weights.

  • smoothing replaces an empty cell in units of weight and is not rescaled with the weights.

  • logistic_regression(), stepwise(), roc_auc_interval() and delong_test() read the weights as frequency weights, so their standard errors count the total weight as the number of observations. Weights that correct for sampling, such as inverse sampling rates, make these standard errors too small.

Periods and thresholds#

  • Periods are ordered as their categories when they are categorical and sorted otherwise. Period 1 of a term structure or an expected credit loss is the first period after its starting point, such as the reporting date, and expected_credit_loss() discounts a default in period \(t\) over \(t\) periods.

  • A threshold is compared as the rule it implements is worded. A cut-off approves the scores at or below it. significant_increase() flags a PD increase only when it exceeds its thresholds, and assign_stages() moves a loan to stage 2 when it is more than stage_2_days past due and to stage 3 when it is at least stage_3_days past due, as IFRS 9 words its 30-day and 90-day presumptions.

Errors and warnings#

  • Invalid input raises ValueError, and so does a model that cannot be fitted, such as one with separated classes, which raises kivi.selection.SeparationError. The message names the argument and, where a single value is at fault, shows the value that was received:

>>> bin_edges([1, 2, 3], bins=0)
Traceback (most recent call last):
    ...
ValueError: bins must be a positive integer, got 0
>>> roc_auc([0.1, 0.9, 0.4], [0, 1, 2])
Traceback (most recent call last):
    ...
ValueError: target must contain only 0 and 1, got 2

  • A UserWarning means that the result differs from the request, for example fewer bins than requested because of tied values, and says what to change. kivi.univariate.profile_table() records such ties in a column instead, so that profiling many columns raises no warnings.

  • A RuntimeWarning means that a fit stopped before it converged.

  • A FutureWarning announces a change of the public API one minor version before it takes effect.
