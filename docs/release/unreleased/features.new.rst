* The new module ``kivi.features`` computes time-window features of event data, such as transactions, point in time. ``window_features`` aggregates the events of each entity over windows that end at the observation time of each row of an observation table, such as the application date, and never uses an event at or after that time. Windows count calendar months, as ``"3M"``, or days, as ``"90D"``, and a pair such as ``("6M", "3M")`` is the period before the most recent one; ``closed="right"`` includes the events at the observation time instead. The aggregations are ``count``, ``sum``, ``mean``, ``min``, ``max``, ``std``, ``nunique``, ``first``, ``last`` and ``days_since_last``, ``ratios`` divides two features, and ``prefix`` names the features of filtered events. The columns are named ``{prefix}{column}_{aggregation}_{window}`` next to ``{prefix}events_{window}``, the number of events of each window. The events are sorted once and the bounds of every window found by binary search, so a million events and a hundred thousand observations take well under a second.
* ``kivi.features.FeatureSpec`` keeps the definitions of one or more groups of window features and their ratios, computes them on any sample with ``compute`` and saves them as versioned JSON with ``to_json`` and ``from_json``, so that development and production compute the same features. Nothing in it is fitted to data.
