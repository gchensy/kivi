示例数据#

kivi.datasets 提供五类示例数据：真实的银行营销数据，每位客户一行，带二分类目标；合成的贷款面板数据，每笔贷款每个月一行；合成的贷款申请数据，每个申请人一行，带审批决策；合成的申请人账户交易流水，每笔交易一行；以及合成的违约贷款，每笔贷款一行，连同其清收现金流，每笔现金流一行。 load_bank() 、 make_loan_panel() 、 make_applications() 、 make_transactions() 、 make_defaults() 和 make_recoveries() 分别返回这些数据。

银行营销数据#

load_bank() 读取 Bank Marketing 数据集中的 4,521 位客户。数据包含 16 个特征和整数标签 target ：1 表示客户认购了定期存款。

>>> from kivi.datasets import load_bank
>>> data = load_bank()
>>> list(data.columns)
['age', 'job', 'marital', 'education', 'default', 'balance', 'housing', 'loan',
 'contact', 'day', 'month', 'duration', 'campaign', 'pdays', 'previous',
 'poutcome', 'target']
>>> data["target"].value_counts().to_dict()
{0: 4000, 1: 521}

本文档中的示例按行的位置切分出两个样本，仅用于演示；这一切分不代表时间顺序。

合成贷款面板#

make_loan_panel() 模拟一个分期贷款资产组合的月度历史，供 Vintage 与滚动率分析 中的 Vintage 分析和滚动率分析使用。数据是生成的，并非取自真实的资产组合；同一个 rng 种子总是给出同样的面板：

>>> from kivi.datasets import make_loan_panel
>>> panel = make_loan_panel(n_loans=5000, n_months=24, rng=0)
>>> panel.shape
(59295, 8)
>>> panel.groupby("cohort")["loan_id"].nunique().agg(["min", "max"]).to_dict()
{'min': 188, 'max': 234}

贷款随机分布在从 2024 年 1 月开始的 n_months 个放款月中；每笔贷款在账上的每个月末都有一行，直到最后一个放款月的下一个月。各列如下：

列

含义

loan_id

贷款标识，随放款月份递增。

cohort

放款月份，为月度 pandas.Period 。

month

观测所在月份，即 cohort + month_on_book 。

month_on_book

放款后经过的月数（账龄），从 1 开始。

term

月供期数：12、24 或 36。

amount

放款金额。

balance

月末的剩余本金。

status

月末的逾期天数，为有序分类变量： current 、 1-29 、 30-59 、 60-89 和 90+ 。

面板的模拟方式#

每笔贷款按月等额本息还款，月利率为 1%。其状态记录自最早一期未还期款到期以来的月数：一个月为 1-29 ，两个月为 30-59 ，三个月为 60-89 ，四个月及以上为 90+ 。在期限内，这就是逾期未还的期数。每个月：

  • 正常贷款漏缴当期期款的概率在账龄第六个月达到峰值，之后下降，并乘以该贷款和所在批次各自的风险系数；

  • 逾期贷款要么还清全部欠款、回到正常，要么只还一期、保持原状态，要么完全不还、滚动到下一个档位（期限结束后也是如此）；档位越靠后，回到正常的可能越小，滚动的可能越大；

  • 90+ 的贷款不再还款，因此其状态和余额保持不变。

贷款在还清最后一期的当月离开面板；如果曾经逾期，这可能发生在期限之后。贷款不会被核销，只有给出 prepayment 时才会提前还款。

提前还款#

prepayment 是正常贷款在最后一期到期之前一次还清全部余额的月度概率，供 存续期 PD 与预期信用损失 中的生存表使用。默认值 0 给出上面的面板，与以前的版本相同。每个月，上月末为正常状态（每笔贷款在放款时都是如此）、且除本月到期的一期外还有剩余期数的贷款，以该概率提前还款，与其风险无关。该贷款当月余额为 0，此后不再有记录，因此各列保持不变：期限之前余额为 0 表示提前还款，期限当月或之后余额为 0 表示按期还清。

>>> repaying = make_loan_panel(n_loans=5000, n_months=24, prepayment=0.02, rng=0)
>>> last = repaying.groupby("loan_id").tail(1)
>>> repaid = last["balance"] == 0
>>> early = repaid & (last["month_on_book"] < last["term"])
>>> int(early.sum()), int((repaid & ~early).sum()), int((last["status"] == "90+").sum())
(962, 454, 182)

每月 2% 的概率使 5,000 笔贷款中的 962 笔提前还款。提前还款使用单独的随机数，在其他随机数全部抽取之后才抽取，因此在同一个 rng 下，每笔贷款在提前还款之前的路径都与不给 prepayment 时相同。于是能在账上留到期限或达到 90+ 的贷款变少：454 笔按期还清，182 笔达到 90+，而没有提前还款时分别为 584 笔和 205 笔。

经济周期#

correlation 和 factors 加入一个经济周期，供 存续期 PD 与预期信用损失 中的转移矩阵使用。每个月，一个系统因子按 conditional_matrix() 的单因子模型使所有贷款的还款一起变化：尚未逾期 90 天的贷款，在当月因子为负时更常漏缴当期期款或没有还清欠款，为正时更少；对因子取平均时，它保持原来的概率。 correlation 是因子的资产相关系数；默认值 0 得到上面的面板，与以前版本相同。 factors 给出从 2024 年 2 月起每个月的因子，以便与估计值比较。不给 factors 时，因子从 rng 抽取，排在所有其他随机数之后。一直处于坏经济或好经济的周期会改变达到 90+ 的贷款数：

>>> def reached_90(panel):
...     return int((panel.groupby("loan_id").tail(1)["status"] == "90+").sum())
>>> bad = make_loan_panel(n_loans=5000, n_months=24, correlation=0.05, factors=[-1.0] * 24, rng=0)
>>> good = make_loan_panel(n_loans=5000, n_months=24, correlation=0.05, factors=[1.0] * 24, rng=0)
>>> reached_90(bad), reached_90(good)
(450, 68)

每个月的因子都为 −1 时，有 450 笔贷款达到 90+；都为 1 时为 68 笔，没有周期时为 205 笔。因子使正常贷款的漏缴与逾期贷款的回到正常和滚动一起变化，但不影响 prepayment 的提前还款。

合成贷款申请#

make_applications() 模拟由现行评分卡和两条政策规则决定审批的贷款申请，供 拒绝推断 中的拒绝推断和 政策规则 中的政策规则使用。每个申请人（包括被拒绝的申请人）都有真实的违约标记，以便把推断的结果与真实结果比较。同一个 rng 种子总是给出同样的申请数据：

>>> from kivi.datasets import make_applications
>>> applications = make_applications(n_applicants=10000, rng=0)
>>> applications.shape
(10000, 10)
>>> print(applications["approved"].mean())
0.677

各列为：

列

含义

age

年龄（岁），从 18 到 75。

income

月收入，取整到十位。

debt_to_income

每月还债额与收入之比，保留两位小数。

inquiries

近六个月的征信查询次数。

housing

分类变量： own 、 mortgage 或 rent 。

employment

分类变量： permanent 、 temporary 或 self_employed 。

incumbent_pd

决定该申请的评分卡给出的 PD，保留四位小数。

policy_decline

若某条政策规则拒绝了该申请（无论其 PD 如何）则为 True，规则为负债收入比高于 0.6 或年龄低于 21 岁。

approved

若 incumbent_pd 低于 0.15 且没有政策规则拒绝该申请，则为 True。

target

申请人违约为 1，否则为 0。

risk

仅在 include_risk=True 时给出：隐藏风险因子，是不取整的标准正态抽样值。

申请数据的模拟方式#

违约概率随负债收入比和征信查询次数上升，随年龄和收入下降，租房者以及临时雇佣和自雇的申请人违约概率更高。不在任何列中的隐藏风险因子（除非用 include_risk=True 要求给出）也会提高违约概率，征信查询次数也随该因子增加。

现行评分卡对各特征的权重不同，并且不使用 housing 。它还像手握征信报告的审批人员一样，能看到隐藏风险因子的一部分。因此，在特征相同时，拒绝申请人比获批申请人风险更高，只用获批申请人拟合的模型会低估拒绝申请人的违约频率，见 拒绝推断 。总体而言，拒绝申请人的违约频率是获批申请人的三倍：

>>> eligible = applications[~applications["policy_decline"]]
>>> eligible.groupby("approved")["target"].mean().round(3)
approved
False    0.301
True     0.097
Name: target, dtype: float64

警告

实际中只有获批申请人的结果是已知的。给出拒绝申请人的 target 只是为了评估拒绝推断；用它拟合模型会使拒绝推断失去意义。 risk 也是如此，它是任何数据集中都没有的信息：给出它是为了模拟依赖于它的数据，例如下面的交易流水，不能用它拟合模型。

合成交易流水#

make_transactions() 模拟 make_applications() 中每个申请之前的账户交易流水：此前十二个月内的银行卡消费、取现和分期还款。它们是计算时间窗特征的事件数据，例如最近三个月的取现次数。数据是生成的，并非取自真实账户，同一个 rng 种子总是给出同样的交易流水。

交易流水取决于申请人的隐藏风险因子和收入，而不取决于结果。 make_applications 在 include_risk=True 时把该因子作为 risk 列返回，其他列及其背后的随机抽样保持不变。申请数据也没有日期，因此示例为每个申请指定一个日期，按行的顺序均匀分布在 2024 年，并把该列的列名作为 application_date 传入：

>>> import numpy as np
>>> import pandas as pd
>>> from kivi.datasets import make_transactions
>>> applications = make_applications(n_applicants=10000, include_risk=True, rng=0)
>>> days = pd.to_timedelta(np.arange(10000) * 366 // 10000, unit="D")
>>> applications["application_date"] = pd.Timestamp("2024-01-01") + days
>>> transactions = make_transactions(applications, application_date="application_date", rng=0)
>>> transactions.shape
(443130, 5)
>>> transactions.head(3)
   applicant_id           timestamp   amount       kind merchant_category
0             0 2023-01-02 14:45:14   201.00   purchase            dining
1             0 2023-01-06 12:12:03  1032.63  repayment               NaN
2             0 2023-02-08 04:22:55   421.14   purchase            online

application_date 是必需的。它可以是申请数据某一列的列名（如这里），可以是所有申请共用的一个日期，也可以是与申请数据索引相同的 Series；日期的读取方式与 delinquency_panel() 相同：时间部分会被忽略，时区会被去掉，数字和 Period 会报错，所以 Period 列要先用 .dt.to_timestamp() 转换。交易的申请人 ID 取申请的索引标签。时间窗所截止的观察表，每个申请一行，含申请人 ID 和日期，可由申请数据及其日期得到。它们沿用申请数据的索引，这样为它们算出的特征可以拼回申请数据：

>>> observations = pd.DataFrame(
...     {"applicant_id": applications.index, "application_date": applications["application_date"]},
...     index=applications.index,
... )
>>> observations.head(2)
   applicant_id application_date
0             0       2024-01-01
1             1       2024-01-01

交易流水的列为：

列

含义

applicant_id

申请人在申请数据中的索引标签。

timestamp

交易发生的时间，精确到秒。

amount

金额，为正，保留两位小数。

kind

分类变量： purchase 、 cash_withdrawal 或 repayment 。

merchant_category

分类变量，有八个类别，例如 grocery 和 travel ，用于消费交易，其他类型的交易为缺失。

申请人的交易落在申请日期之前的 n_months 个日历月内，默认十二个月：从 n_months 个月之前的那一天（按 pandas.DateOffset 的方式计算）开始，到申请日期为止，不含申请日期本身。因此，“申请日期之前最近三个月”这样的时间窗正好切在交易的分界上，申请日期当天及之后也没有会泄漏进时间窗的交易。

交易流水的模拟方式#

各月的交易相互独立地生成。一年中，申请人平均约有 25 笔消费、8 笔取现和 11 笔还款，共 44 笔交易。一笔消费约为月收入的 4.5%，一笔取现约为 3%，还款则是 income * debt_to_income 对应的分期款，各申请人之间相差约 20%。 income 较高的申请人消费和取现略多一些，起始于 11 月和 12 月的月份消费更频繁。现行评分卡按 incumbent_pd 评为风险较高的申请人取现更多、漏还也更多， risk 较高的申请人也是如此。

risk 还会带动一种在申请前逐步累积的压力。它在申请前三到九个月开始，在最后一个月最强。压力水平随风险加噪声而上升，从几乎没有到一个有界的最大值。受压时，取现更频繁、金额更大，消费略有减少，还款更可能漏还，或少还至多一成。申请人的基线各不相同，压力对风险的反映也带有噪声，所以没有哪个特征能很好地预测结果。交易流水不取决于 target ：它们是在结果产生之前根据风险生成的，就像贷款人观察到的那样。

最近三个月的取现次数体现了这一信号。这里用 pandas 对上面的交易流水和观察表计数；违约率从没有取现的申请人的 8%，升到取现五次及以上的申请人的 27%：

>>> merged = transactions.merge(observations, on="applicant_id")
>>> last_3_months = merged["timestamp"] >= merged["application_date"] - pd.DateOffset(months=3)
>>> cash = merged[last_3_months & (merged["kind"] == "cash_withdrawal")]
>>> cash_3m = cash.groupby("applicant_id").size().reindex(applications.index, fill_value=0)
>>> cash_3m.name = "cash_withdrawals_3m"
>>> rate = applications["target"].groupby(cash_3m.clip(upper=5)).agg(["size", "mean"])
>>> rate.round(3)
                     size   mean
cash_withdrawals_3m
0                    1704  0.081
1                    2010  0.105
2                    1539  0.129
3                    1154  0.137
4                     767  0.192
5                    2826  0.268

这个特征的 IV 由 profile_table() 按 单变量概况 中的方式计算，为 0.31，信号清晰但不算强：

>>> from kivi.univariate import profile_table
>>> profile_table(cash_3m.to_frame(), applications["target"])[["iv"]].round(3)
                       iv
variable
cash_withdrawals_3m  0.31

现行评分卡只看到风险的一部分，所以对于它评分相近的申请人，交易流水仍能说明他们的违约情况。在按 incumbent_pd 分成的两半中，违约率仍随取现次数上升：

>>> above = applications["incumbent_pd"] > applications["incumbent_pd"].median()
>>> half = pd.Series(np.where(above, "above", "below"), index=applications.index, name="incumbent_pd")
>>> applications["target"].groupby([half, cash_3m.clip(upper=4)]).mean().unstack(0).round(3)
incumbent_pd         above  below
cash_withdrawals_3m
0                    0.163  0.052
1                    0.167  0.070
2                    0.194  0.081
3                    0.201  0.073
4                    0.310  0.098

其他时间窗特征有的更弱，有的更强。按默认的五个分箱计算，最近三个月的消费笔数的 IV 为 0.05，最近三个月的还款相对此前三个月的还款的 IV 为 0.18，最近三个月取现金额相对收入的 IV 为 0.31。 window_features() 无需合并就能计算这类特征，一次可以计算多个窗口和多列，见 时间窗特征 。

警告

交易流水取决于 risk ，而任何贷款人都没有它：它只存在于模拟的申请数据中。请用交易流水来学习时间窗特征的用法，而不要用它来估计行为对违约的预测能力。

合成违约贷款与回收现金流#

make_defaults() 模拟 2018 年至 2024 年间违约的贷款， make_recoveries() 模拟其清收过程的现金流：回收、费用和治愈，由此得到每笔贷款的实际 LGD。循环额度还带有违约前 12 个月的额度和已提用金额，由此得到其实际 CCF。数据是生成的，并非取自真实的资产组合；同一个 rng 种子总是给出同样的贷款和现金流：

>>> from kivi.datasets import make_defaults, make_recoveries
>>> defaults = make_defaults(n_defaults=2000, rng=0)
>>> defaults.shape
(2000, 9)
>>> columns = ["loan_id", "segment", "default_date", "ead", "collateral_value", "closing_date"]
>>> defaults[columns].head(3)
   loan_id    segment default_date        ead  collateral_value closing_date
0        1    secured   2018-01-01  307147.39          312800.0   2019-08-17
1        2  revolving   2018-01-01    2471.68               0.0   2020-11-21
2        3  unsecured   2018-01-01   23456.26               0.0   2018-12-29
>>> revolving = defaults[defaults["segment"] == "revolving"]
>>> revolving[["loan_id", "ead", "limit", "drawn", "discount_rate"]].head(3)
    loan_id       ead    limit     drawn  discount_rate
1         2   2471.68   5100.0   2043.04           0.05
5         6   3545.43   4700.0   2119.49           0.05
15       16  21057.35  21500.0  20902.37           0.05

违约贷款表的列为：

列

含义

loan_id

贷款标识，从 1 开始，随违约日期递增。

segment

分类变量： secured 、 unsecured 或 revolving ，分别约占贷款的 40%、35% 和 25%。

default_date

违约日期，从 2018 年到 2024 年。

ead

违约风险敞口，即违约当日的未偿金额，保留到分。

limit

循环额度在参考日（违约前 12 个月）的额度，取整到百位；其他分段为缺失值。

drawn

循环额度在参考日的已提用金额，保留到分；其他分段为缺失值。

collateral_value

有抵押贷款在违约时的抵押品价值，取整到百位；其他分段为 0。

discount_rate

把清收现金流折现到违约日的年折现率：违约当月的模拟三个月货币市场利率加 5 个百分点，符合 EBA/GL/2017/16 第 143 段的规定。

closing_date

清收结束的日期，即治愈、处置抵押品或核销未回收部分的日期；在数据截止日 2025 年 6 月 30 日仍未结案的清收为缺失值。

make_recoveries() 接收违约贷款表，返回每笔现金流一行，按贷款和日期排序。第一笔贷款是有抵押贷款：经过三笔法律费用和借款人的两笔还款后，抵押品在结案日处置，处置费用为所得的 3%：

>>> flows = make_recoveries(defaults, rng=0)
>>> flows.shape
(11497, 4)
>>> flows.head(7)
   loan_id       date     amount      kind

清收的模拟方式#

一次清收至少持续三个月，即治愈的观察期。约 30% 的有抵押贷款、10% 的无抵押贷款和 15% 的循环额度会治愈，平均用时七个月，其余贷款进入处置：

  • 已治愈的贷款在清收期间偿还部分欠款，有时产生少量费用，并在结案日治愈；

  • 有抵押贷款在清收期间偿还少量款项，并在结案日处置抵押品。银行在其债权（违约风险敞口加上年利率 4% 到 10% 的罚息）范围内收回处置所得，并支付处置所得 3% 的处置费用和若干法律费用。清收平均持续约两年半；

  • 无抵押贷款或循环额度平均分别收回其违约风险敞口的约 17% 或 22%，分多笔收回，并产生若干催收费用。清收平均分别持续一年半或 15 个月。

约 5% 的贷款还在违约前 90 天内有一笔法律费用，EBA/GL/2017/16 第 144 段把它计入经济损失；3% 的处置有占违约风险敞口 10% 到 40% 的诉讼费用。有抵押贷款在违约时的贷款价值比中位数为 75%，有些贷款的欠款高于其抵押品的价值。现金流到数据截止日 2025 年 6 月 30 日为止：届时仍未结案的清收只有截止日之前的现金流，之后没有。

实际 LGD#

贷款的实际 LGD 是其经济损失与违约风险敞口之比 (ead + PV(costs) - PV(recoveries)) / ead ，其中治愈计为回收，现值按年折现率 discount_rate 把每笔现金流折现到违约日，期间的天数除以 365。由于费用是负的金额，LGD 等于 1 减去全部现金流的现值与违约风险敞口之比。这里用 pandas 计算：

>>> dated = flows.merge(defaults[["loan_id", "default_date", "discount_rate"]], on="loan_id")
>>> years = (dated["date"] - dated["default_date"]).dt.days / 365
>>> present_value = dated["amount"] * (1 + dated["discount_rate"]) ** -years
>>> loans = defaults.set_index("loan_id")
>>> net = present_value.groupby(dated["loan_id"]).sum().reindex(loans.index, fill_value=0)
>>> lgd = (1 - net / loans["ead"]).rename("lgd")

只有已结案的清收才有实际 LGD。它们的 LGD 呈双峰分布：多数有抵押贷款的损失不到其违约风险敞口的 10%，多数无抵押贷款和循环额度的损失超过 70%：

>>> import numpy as np
>>> import pandas as pd
>>> closed = loans["closing_date"].notna()
>>> labels = ["below 0", "0-0.1", "0.1-0.3", "0.3-0.7", "0.7-0.9", "0.9-1", "1 and above"]
>>> edges = [-np.inf, 0, 0.1, 0.3, 0.7, 0.9, 1, np.inf]
>>> band = pd.cut(lgd[closed], edges, right=False, labels=labels)
>>> pd.crosstab(band, loans.loc[closed, "segment"])

>>> cured = pd.Series(loans.index.isin(flows.loc[flows["kind"] == "cure", "loan_id"]), loans.index)
>>> by_outcome = lgd[closed].groupby([loans["segment"], cured.rename("cured")], observed=True)

38 个负的 LGD 都来自有抵押贷款，其抵押品覆盖了含罚息的债权，按折现率计算，收回的金额超过了违约风险敞口。119 个高于 1 的 LGD 来自费用超过回收的贷款。EBA/GL/2017/16 第 160 和 162 段要求两者都保留在数据中：计算平均值时负的 LGD 计为 0，远高于 1 的 LGD 需要找出原因。这里两者都不截断。

未结案的清收尚未结束，因此其迄今为止现金流得到的 LGD 不是实际 LGD。最主要的是，未结案清收的抵押品都还没有处置：

>>> workout = closed.map({True: "closed", False: "open"}).rename("workout")
>>> lgd.groupby([loans["segment"], workout], observed=True).mean().unstack().round(3)

仍未结案的正是时间长的清收，因此已结案的清收中治愈的比例也高于全部清收。计算平均值或回测实际 LGD 之前，请先剔除未结案的清收，这是 EBA/GL/2017/16 第 154 段和 模型验证 中欧洲央行的回测所要求的。

实际 CCF#

循环额度的实际 CCF 是其参考日的未提用额度中到违约时被提用的比例 (ead - drawn) / (limit - drawn) ，其中额度和已提用金额都取参考日的值。用满或超出额度的循环额度没有定义 CCF：

>>> undrawn = revolving["limit"] - revolving["drawn"]
>>> ccf = ((revolving["ead"] - revolving["drawn"]) / undrawn).where(undrawn > 0)
>>> int(ccf.isna().sum()), int((ccf < 0).sum()), int(ccf.between(0, 1).sum()), int((ccf > 1).sum())
(25, 43, 376, 45)
>>> print(round(ccf.median(), 3))
0.554

在参考日有未提用额度的 464 个循环额度中，376 个的 CCF 在 0 到 1 之间，中位数为 0.55。CCF 为负的循环额度在违约前偿还了部分余额，CCF 高于 1 的循环额度在违约时超出了额度。CRR3 第 182(1) 条规定，估计 CCF 时负的 CCF 计为 0，而高于 1 的 CCF 保留，因为参考数据不得封顶在 100%。

警告

这些违约贷款及其现金流是为演示实际 LGD 和 CCF 的计算而模拟的，各种效应的大小由模拟设定。请用它们学习这些计算的做法，而不是估计真实资产组合的 LGD 或 CCF。
