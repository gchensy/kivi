政策规则#

除了评分，信贷政策还有一些规则，无论评分如何都会拒绝申请人或转人工审核：负债收入比超过上限、申请人未达最低年龄、近期征信查询过多。每条规则都要回答同样的问题：它命中多少申请人，这些申请人风险有多高，哪些拒绝只取决于它，以及它在之前的规则之外又增加了什么。 kivi.rules 回答这些问题： rule_table() 统计每条规则的命中和事件， rule_set_table() 按顺序执行规则，即决策瀑布表，并用 cutoff_table() 的各列描述规则执行后仍然通过的客群。 rule_candidates() 提出新规则：它在每个数值变量中搜索命中客群比整个样本风险更高的阈值。

规则属于上一篇指南 信贷策略 中的信贷策略，后者决定评分的截断点；规则之后是下一篇指南，把模型投入生产的 分箱方案 。

定义#

规则是关于申请人数据的一个条件，以一列布尔值传入，规则命中处为 True，即拒绝或标记该申请人之处。设样本有 \(n\) 个申请人，一条规则命中其中的申请人 \(H\) ，已知结果为 \(K\) ，事件为 \(E\) ，则

\[\text{命中率} = \frac{\lvert H \rvert}{n}, \qquad \text{事件率} = \frac{\lvert H \cap E \rvert}{\lvert H \cap K \rvert}, \qquad \text{提升度} = \frac{\text{事件率}}{\lvert E \rvert / \lvert K \rvert}, \qquad \text{召回率} = \frac{\lvert H \cap E \rvert}{\lvert E \rvert}.\]

提升度把命中的事件率与整个样本的事件率相比，召回率是规则命中的事件占全部事件的比例。一条规则的独有命中，是它命中、且规则集中其他规则都没有命中的申请人。

规则集按顺序执行其规则 \(H_1, \dots, H_m\) 。规则 \(j\) 的新增命中是之前的规则都没有命中的申请人，执行它之后仍然通过的申请人，是前 \(j\) 条规则都没有命中的申请人：

\[N_j = H_j \setminus (H_1 \cup \dots \cup H_{j-1}), \qquad A_j = \overline{H_1 \cup \dots \cup H_j}.\]

通过客群 \(A_j\) 的描述方式与截断点描述其客群相同：规模、事件率 \(\lvert A_j \cap E \rvert / \lvert A_j \cap K \rvert\) ，以及前 \(j\) 条规则拒绝的事件和非事件分别占全部事件和全部非事件的比例。给出 weights 时，每个计数都是权重之和。

计算示例#

八个申请人、三条规则、三个事件。 high_debt 命中申请人 0、1 和 5， young 命中申请人 1 和 2， inquiries 命中申请人 2 和 3；申请人 0、1 和 3 违约：

>>> import numpy as np
>>> import pandas as pd
>>> from kivi.rules import rule_set_table, rule_table
>>> example = pd.DataFrame({
...     "high_debt": [1, 1, 0, 0, 0, 1, 0, 0],
...     "young": [0, 1, 1, 0, 0, 0, 0, 0],
...     "inquiries": [0, 0, 1, 1, 0, 0, 0, 0],
... })
>>> example_target = [1, 1, 0, 1, 0, 0, 0, 0]
>>> rule_table(example, example_target)[["hits", "unique_hits", "event", "event_rate", "lift"]].round(3)
           hits  unique_hits  event  event_rate   lift
rule
high_debt     3            2      2       0.667  1.778
young         2            0      1       0.500  1.333
inquiries     2            1      1       0.500  1.333

high_debt 命中三个申请人，其中两人违约：事件率为 2/3，而全部八人为 3/8，提升度为 \((2/3) / (3/8) = 1.78\) 。申请人 1 也被 young 命中，因此只因 high_debt 而被拒绝的有两人。 young 没有独有命中：它命中的每个申请人也被另一条规则命中。按顺序执行时，每条规则只统计之前的规则留下的申请人：

>>> rule_set_table(example, example_target)[["new_hits", "new_event", "approved", "approved_event_rate"]]
           new_hits  new_event  approved  approved_event_rate
rule
high_debt         3          2         5                 0.20
young             1          0         4                 0.25
inquiries         1          1         3                 0.00

young 只新增申请人 2， inquiries 只新增申请人 3，即最后一个事件。剩下通过的三个申请人 4、6 和 7 没有事件。

申请数据上的规则#

示例使用 make_applications() 模拟的申请数据，见 示例数据 。其中一部分申请人无论评分如何都被两条政策规则拒绝：负债收入比高于 0.6，以及年龄低于 21 岁。再加上两条候选规则：近六个月征信查询三次及以上，以及月收入低于 1,500。每条规则都是由数据得到的一列布尔值：

>>> from kivi.datasets import make_applications
>>> applications = make_applications(rng=0)
>>> rules = pd.DataFrame({
...     "high_debt": applications["debt_to_income"] > 0.6,
...     "young": applications["age"] < 21,
...     "many_inquiries": applications["inquiries"] >= 3,
...     "low_income": applications["income"] < 1500,
... })
>>> target = applications["target"]

两条政策规则正好给出数据中的 policy_decline 列：

>>> (rules["high_debt"] | rules["young"]).equals(applications["policy_decline"])
True

模拟数据给每个申请人都提供了结果，被拒的申请人也不例外，因此前面的示例在规则命中的所有申请人上衡量每条规则。真实数据只有已通过申请人的结果； 未知结果 说明这时各表报告的是什么。

命中表#

rule_table() 在每个申请人上独立评估每条规则，不受其他规则影响。不传入目标时，它只统计命中，而命中对每个申请人都是已知的：

>>> rule_table(rules)
                hits  hit_rate  unique_hits
rule
high_debt        399    0.0399          340
young            377    0.0377          289
many_inquiries   799    0.0799          699
low_income       482    0.0482          379

传入目标后，再加上命中申请人的结果：

>>> table = rule_table(rules, target)
>>> table[["known", "event", "event_rate", "lift"]].round(3)
                known  event  event_rate   lift
rule
high_debt         399    125       0.313  1.946
young             377     89       0.236  1.466
many_inquiries    799    261       0.327  2.029
low_income        482    122       0.253  1.572
>>> table[["recall", "unique_event"]].round(3)
                recall  unique_event
rule
high_debt        0.078            97
young            0.055            63
many_inquiries   0.162           216
low_income       0.076            88

负债收入比高于 0.6 的申请人违约率为 31.3%，几乎是全部申请人 16.1% 的两倍，因此这条规则的提升度为 1.95。它命中 4% 的申请人和 7.8% 的事件。 many_inquiries 命中的申请人是它的两倍，事件率略高，抓住了 16.2% 的事件。规则之间的重叠很少：负债收入比高的 399 个申请人中，有 340 人没有被其他任何规则命中。

列

含义

hits, hit_rate

规则命中的申请人，及其占全部申请人的比例。

unique_hits

被这条规则命中、且不被规则集中其他任何规则命中的申请人：完全取决于这条规则的拒绝。

known

结果已知的命中。

event, event_rate

命中中的事件，及其占结果已知命中的比例。

lift

event_rate 除以全部已知结果的事件率。提升度为 2，表示命中申请人的违约频率是整个样本的两倍。

recall

规则命中的事件占全部已知事件的比例。

unique_event

独有命中中的事件。

表中各行相加没有意义，因为被两条规则命中的申请人在两行中都会计入。当一条规则的事件率明显高于业务盈亏平衡的事件率时，它的拒绝才是值得的，这与 信贷策略 中判断截断点的边际坏账率相同。要比较同一规则的不同阈值，可每个阈值传入一列，例如 inquiries >= 2 、 >= 3 和 >= 4 。

重叠矩阵#

两条规则的重叠，是两者都命中的申请人数。所有规则两两之间的重叠，就是把规则各列记为 0 与 1 后的矩阵乘积，无需专门的函数：

>>> hits = rules.astype(int)
>>> overlap = hits.T @ hits
>>> overlap
                high_debt  young  many_inquiries  low_income
high_debt             399     13              28          20
young                  13    377              33          44
many_inquiries         28     33             799          43
low_income             20     44              43         482

对角线上是 rule_table() 的 hits 。每一行除以其对角线元素，得到行规则的命中中同时被列规则命中的比例：

>>> overlap.div(np.diag(overlap), axis=0).round(3)
                high_debt  young  many_inquiries  low_income
high_debt           1.000  0.033           0.070       0.050
young               0.034  1.000           0.088       0.117
many_inquiries      0.035  0.041           1.000       0.054
low_income          0.041  0.091           0.089       1.000

重叠最大的是 young 和 low_income ：年轻申请人中有 11.7% 的月收入低于 1,500，因为数据中收入随年龄增长。请先把布尔列转换为整数：两列布尔值的乘积仍是布尔值，只要有一个申请人同时被两条规则命中就为 True，而不是计数。改为乘以目标， hits.T @ hits.mul(target, axis=0) ，则统计两条规则都命中的事件。

决策瀑布表#

rule_set_table() 按列的顺序执行规则。每条规则在之前的规则留下的申请人中拒绝它命中的那些，因此每个命中只计一次，计在第一条命中它的规则下：

>>> waterfall = rule_set_table(rules, target)
>>> waterfall[["new_hits", "new_event", "approved", "approval_rate"]].round(3)
                new_hits  new_event  approved  approval_rate
rule
high_debt            399        125      9601          0.960
young                364         84      9237          0.924
many_inquiries       738        232      8499          0.850
low_income           379         88      8120          0.812
>>> waterfall[["approved_event", "approved_event_rate", "rejected_event_share"]].round(3)
                approved_event  approved_event_rate  rejected_event_share
rule
high_debt                 1485                0.155                 0.078
young                     1401                0.152                 0.130
many_inquiries            1169                0.138                 0.274
low_income                1081                0.133                 0.329
>>> waterfall["rejected_non_event_share"].round(3)
rule
high_debt         0.033
young             0.066
many_inquiries    0.126
low_income        0.161
Name: rejected_non_event_share, dtype: float64

第一行就是 high_debt 本身。 young 新增 364 个申请人，即它命中的 377 人减去已被 high_debt 拒绝的 13 人。执行完全部四条规则后，通过 8,120 个申请人，占 81.2%，事件率为 13.3%，而不是 16.1%。这些规则拒绝了 32.9% 的事件和 16.1% 的非事件。

列

含义

new_hits, new_event

被这条规则命中、且之前的规则都没有命中的申请人，以及其中的事件。

approved, approval_rate

到这条规则为止没有被任何规则命中的申请人，及其占全部申请人的比例。

approved_event, approved_event_rate

通过申请人中的事件，及其占结果已知的通过申请人的比例。

rejected_event_share

到这条规则为止被某条规则拒绝的事件占全部已知事件的比例。

rejected_non_event_share

到这条规则为止被某条规则拒绝的非事件占全部已知非事件的比例：这些规则放弃的优质业务。

累计列与 cutoff_table() 的各列相同，因此一行可以像截断点一样解读：所有结果都已知时，它等于 cutoff_table(declined, target, cutoffs=[0]) 的结果，其中 declined 对被到该行为止的某条规则命中的申请人为 1，对其他申请人为 0。

评分截断点也是一条规则。模拟数据中的审批决策，就是两条政策规则加上 incumbent_pd 的截断点 0.15 组成的瀑布表，其最后一行通过的正好是标记为 approved 的申请人：

>>> decisions = rules[["high_debt", "young"]].assign(high_pd=applications["incumbent_pd"] >= 0.15)
>>> rule_set_table(decisions)[["new_hits", "approved", "approval_rate"]].round(3)
          new_hits  approved  approval_rate
rule
high_debt      399      9601          0.960
young          364      9237          0.924
high_pd       2467      6770          0.677
>>> int(applications["approved"].sum())
6770

规则顺序#

规则的顺序决定了多条规则共同的拒绝记在哪条规则名下，但不决定规则集拒绝哪些申请人。先执行候选规则，候选规则的新增命中增加，政策规则的新增命中减少：

>>> order = ["many_inquiries", "low_income", "high_debt", "young"]
>>> reordered = rule_set_table(rules[order], target)
>>> pd.DataFrame({
...     "policy_first": waterfall["new_hits"],
...     "candidates_first": reordered["new_hits"].reindex(waterfall.index),
... })
                policy_first  candidates_first
rule
high_debt                399               353
young                    364               289
many_inquiries           738               799
low_income               379               439

最后一行描述整个规则集，保持不变：

>>> cumulative = ["approved", "approved_event", "rejected_event_share", "rejected_non_event_share"]
>>> waterfall[cumulative].iloc[-1].equals(reordered[cumulative].iloc[-1])
True

一条规则的新增命中，介于它排在最后时的 rule_table() 中的 unique_hits ，与它排在最前时的 hits 之间： young 排在最后时新增 289 个申请人，排在最前时新增 377 个。因此，独有命中就是从规则集中去掉这条规则后会通过的申请人。独有命中很少的规则，无论命中多少申请人，在其他规则之外都增加不了多少。瀑布表应按规则在生产中执行的顺序报告，例如把不需要征信数据的规则放在前面，因为它们检查起来最便宜。

未知结果#

在真实数据中，只有已通过的申请人才有已知结果：其他人从未获得贷款。对他们传入缺失标签。他们计入命中和 approved ，但不计入 known 、 event 以及各比率和比例：

>>> observed = target.where(applications["approved"])
>>> rule_table(rules, observed)[["hits", "known", "event", "event_rate", "lift"]].round(3)
                hits  known  event  event_rate   lift
rule
high_debt        399      0      0         NaN    NaN
young            377      0      0         NaN    NaN
many_inquiries   799    260     41       0.158  1.620
low_income       482    184     27       0.147  1.507

政策规则拒绝了它们命中的每一个申请人，因此其命中都没有已知结果，它们的事件率无法用它们自己产生的数据来衡量。候选规则则在其命中中已通过的 260 人和 184 人上衡量。在已通过申请人上，它们说明了把候选规则加入现行政策会带来什么变化。把它们放在现行决策之后：

>>> extended = rule_set_table(decisions.join(rules[["many_inquiries", "low_income"]]), observed)
>>> extended[["new_hits", "new_event", "approved", "approved_event_rate"]].round(4)
                new_hits  new_event  approved  approved_event_rate
rule
high_debt            399          0      9601               0.0973
young                364          0      9237               0.0973
high_pd             2467          0      6770               0.0973
many_inquiries       260         41      6510               0.0949
low_income           181         27      6329               0.0934
>>> extended[["approval_rate", "rejected_event_share", "rejected_non_event_share"]].round(3)
                approval_rate  rejected_event_share  rejected_non_event_share
rule
high_debt               0.960                 0.000                     0.000
young                   0.924                 0.000                     0.000
high_pd                 0.677                 0.000                     0.000
many_inquiries          0.651                 0.062                     0.036
low_income              0.633                 0.103                     0.061

现行决策通过 6,770 个申请人，观测到的事件率为 9.73%。两条候选规则会拒绝其中 441 人，使通过率从 67.7% 降至 63.3%，事件率降至 9.34%，以 6.1% 的已知非事件为代价，避开 10.3% 的已知事件。是否划算，取决于一笔好贷款的收益和一笔坏贷款的损失，见 信贷策略 。这张表中的每个数字在实际中都是已知的，因为候选规则拒绝的都是结果已知的申请人。

模拟核对

模拟数据中被拒的申请人确实有结果。被政策规则拒绝的申请人违约率分别为 31.3% 和 23.6%，而观测到的结果无法反映这一点；候选规则在被拒申请人中命中的申请人，风险也远高于在已通过申请人中命中的：

>>> pd.DataFrame({
...     "observed": rule_table(rules, observed)["event_rate"],
...     "all_hits": rule_table(rules, target)["event_rate"],
... }).round(3)
                observed  all_hits
rule
high_debt            NaN     0.313
young                NaN     0.236
many_inquiries     0.158     0.327
low_income         0.147     0.253

现行评分卡已经拒绝了查询次数多的申请人中风险最高的那些，因此其中已通过者的违约率只有全部命中者的一半。在已通过申请人上测得的事件率，描述的是这条规则作为现行政策的补充时的效果，而不是这条规则本身。

缺失值#

rules 中的缺失值会报错，因为数据缺失时规则是否命中，本身就是规则定义的一部分。NumPy 浮点数与 NaN 比较时返回 False，因此由比较得到的规则在数据缺失处不会命中，而且不会给出任何提示。pandas 的可空数据类型则返回缺失值， rule_table() 和 rule_set_table() 会拒绝它：

>>> income = applications["income"].astype("Float64")
>>> income[[0, 1]] = pd.NA
>>> rule_table(pd.DataFrame({"low_income": income < 1500}))
Traceback (most recent call last):
...
ValueError: rules column 'low_income' must not have missing values, got 2; decide whether the rule hits when its data are missing

用 fillna 做出决定： (income < 1500).fillna(True) 拒绝收入未知的申请人， fillna(False) 则通过他们。 target 中的缺失标签不是错误，而是未知结果，见 未知结果 。

样本权重#

与 kivi.strategy 中的函数一样，两个函数都接受 weights ，即每个申请人一个非负频数权重。计数变为权重之和，因此整数权重与重复相应行得到的表相同。按结果抽样的样本保留全部事件和四分之一的非事件，给非事件权重 4，即可还原全部申请人的事件率：

>>> rng = np.random.default_rng(0)
>>> kept = (target == 1) | (rng.random(len(target)) < 0.25)
>>> sample_weights = np.where(target[kept] == 1, 1.0, 4.0)
>>> pd.DataFrame({
...     "unweighted": rule_table(rules[kept], target[kept])["event_rate"],
...     "weighted": rule_table(rules[kept], target[kept], weights=sample_weights)["event_rate"],
...     "everyone": table["event_rate"],
... }).round(3)
                unweighted  weighted  everyone
rule
high_debt            0.676     0.342     0.313
young                0.571     0.249     0.236
many_inquiries       0.632     0.300     0.327
low_income           0.584     0.260     0.253

不加权重时，这个有 3,724 个申请人的样本高估了每个事件率，因为它只保留了四分之一的非事件。加权后的事件率与全部申请人的事件率之差，只来自对非事件的抽样。

搜索规则#

上面的规则来自政策。 rule_candidates() 从数据中提出阈值，一次看一个变量。对每个数值列，它用 tree_edges() （或用 ks_edges()，即 method="ks"）拟合切点，取每个内部切点 \(t\)，保留 > t 或 <= t 中命中者违约更多的一侧。它保留命中至少 min_hit_rate 的申请人且提升度至少为 min_lift 的规则，并按提升度从高到低列出。这里前 6,000 条申请作为开发样本，后 4,000 条作为验证样本：

>>> from kivi.rules import rule_candidates
>>> development, validation = applications.iloc[:6000], applications.iloc[6000:]
>>> columns = ["age", "income", "debt_to_income", "inquiries"]
>>> candidates = rule_candidates(
...     development, development["target"], columns=columns, min_lift=1.5
... )
>>> candidates[["operator", "threshold", "hits", "hit_rate", "event_rate", "lift"]].round(3)
                      operator  threshold  hits  hit_rate  event_rate   lift
rule
inquiries > 3.0              >       3.00   136     0.023       0.412  2.529
inquiries > 2.0              >       2.00   475     0.079       0.347  2.133
debt_to_income > 0.58        >       0.58   283     0.047       0.329  2.018
income <= 1650.0            <=    1650.00   448     0.075       0.279  1.714
income <= 1850.0            <=    1850.00   701     0.117       0.262  1.612
inquiries > 1.0              >       1.00  1475     0.246       0.256  1.574
debt_to_income > 0.42        >       0.42  1162     0.194       0.248  1.522
income <= 1790.0            <=    1790.00   621     0.104       0.246  1.513

不传 columns 时搜索所有数值列，类别列和布尔列会被跳过（在 columns 中指定它们会抛出错误）。表中的计数列 hits、hit_rate、known、event、event_rate 和 lift 与 rule_table() 的列相同，顺序也相同，其值恰好是 rule_table() 对写成布尔列的该规则（见下）报告的值，使用 weights 时也一样：提升度是命中者的事件率除以所有已知结果的事件率。同一变量的几个阈值，如 inquiries > 2 和 inquiries > 1，彼此重叠，是备选关系，因此每个变量选一个。把候选写成布尔列就成了规则， rule_table() 和 rule_set_table() 可以直接使用：

>>> chosen = candidates.loc[["inquiries > 2.0", "debt_to_income > 0.58", "income <= 1850.0"]]
>>> def as_rules(frame, table, special=None):
...     special = special or {}
...     rules = {}
...     for name, row in table.iterrows():
...         values = frame[row["variable"]]
...         hit = values.gt(row["threshold"]) if row["operator"] == ">" else values.le(row["threshold"])
...         # Special codes and missing values hit no threshold rule.
...         rules[name] = (hit & ~values.isin(special.get(row["variable"], []))).fillna(False)
...     return pd.DataFrame(rules)
>>> rule_set_table(as_rules(development, chosen), development["target"])[
...     ["new_hits", "new_event", "approved", "approved_event_rate"]
... ].round(3)
                       new_hits  new_event  approved  approved_event_rate
rule
inquiries > 2.0             475        165      5525                0.147
debt_to_income > 0.58       259         77      5266                0.140
income <= 1850.0            611        145      4655                0.127

阈值和它们的事件率来自同一批申请人，因此偏乐观，就像有监督分箱的 IV 一样。请在搜索没见过的申请人上重新衡量选定的规则：

>>> pd.concat(
...     {
...         "development": rule_table(as_rules(development, chosen), development["target"]),
...         "validation": rule_table(as_rules(validation, chosen), validation["target"]),
...     },
...     axis=1,
... )[[("development", "event_rate"), ("validation", "event_rate")]].round(3)
                      development validation
                       event_rate event_rate
rule
inquiries > 2.0             0.347      0.296
debt_to_income > 0.58       0.329      0.341
income <= 1850.0            0.262      0.256

inquiries 规则的事件率从 34.7% 降到 29.6%，debt_to_income 保持不变，income 几乎不变。这种回落是搜索的代价之一，因此应当用验证样本上的事件率而不是开发样本上的提升度来评价规则。

缺失值和特殊值不命中任何阈值规则，搜索时也把它们排除在拟合之外。 special 给出每列的特殊值，与 fit_spec() 相同。若要拒绝或标记某个特殊值，请把它单独写成一条规则，并用 rule_table() 衡量，其提升度能说明它是否有风险。这里把每第二十个收入替换为特殊值 -1：

>>> coded = development.assign(income=development["income"].mask(np.arange(6000) % 20 == 0, -1))
>>> found = rule_candidates(
...     coded, coded["target"], columns=["income"], special={"income": [-1]}, min_lift=1.2
... )
>>> found[["operator", "threshold", "hits", "lift"]].round(3)
                  operator  threshold  hits   lift
rule
income <= 1640.0        <=     1640.0   419  1.715
income <= 1850.0        <=     1850.0   673  1.597
income <= 1750.0        <=     1750.0   545  1.499
income <= 2420.0        <=     2420.0  1569  1.366
>>> rule_table(pd.DataFrame({"income_unknown": coded["income"] == -1}), coded["target"])[
...     ["hits", "event_rate", "lift"]
... ].round(3)
                hits  event_rate   lift
rule
income_unknown   300       0.133  0.819

没有任何阈值命中这 300 个带特殊值的申请人，他们的违约率为 13.3%，低于样本（提升度 0.82），因此不需要规则。像 as_rules 那样排除特殊值来写规则，候选规则就有表中的计数：

>>> measured = rule_table(as_rules(coded, found, {"income": [-1]}), coded["target"])
>>> measured["hits"].equals(found["hits"]) and np.allclose(measured["lift"], found["lift"])
True

如果不排除特殊值，income <= 1640 也会命中带特殊值的申请人，因为 -1 小于阈值。

切点拟合时最小的箱为 min_hit_rate 的申请人比例，因此搜索既能找到较宽的规则，也能找到较小的高风险尾部，例如上表中询价超过三次的 136 个申请人（2.3%）。

局限#

  • 正在执行的规则拒绝它命中的每一个申请人，因此它产生的结果无法衡量它自己。只有一组即使命中规则也予以通过的测试申请人，或 拒绝推断 ，才能给出它的事件率。

  • 这些表不给出置信区间。已知结果只有几百个时，事件率的不确定性可达几个百分点，两条规则之间的差异可能只是噪声。

  • rule_candidates() 一次只看一个变量，只能找到单个阈值。它不会组合变量，也不搜索类别列，类别列的规则是由您自己写的类别列表。它的候选规则是在同一批申请人上找到并衡量的，因此偏乐观：把它们放进政策之前，请像上面那样在验证样本上用 rule_table() 复核。

  • 一条规则的新增命中取决于规则集的顺序。比较规则时看命中和独有命中，瀑布表则用于某一固定顺序下的决策。

错误与警告#

这两个函数会抛出 ValueError ，不发出警告。读者可能遇到的错误有：

  • 规则列不是布尔值或 0 与 1，例如误传了数据中的原始列： rules column 'inquiries' must contain only booleans or 0 and 1 。请用比较来构造规则，例如 applications["inquiries"] >= 3 。

  • 规则中有缺失值，见上文的 缺失值 。

  • 目标或权重与 rules 的行不对应：某个 Series 的索引不同时，报 rules and target must have identical indices ，例如目标取自全部申请，而规则是在一个子集上构造的；数组长度不同时，报 target must have one label per row of rules 。请对两者选取相同的行，例如 rule_table(rules[kept], target[kept]) 。
