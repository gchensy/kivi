kivi.datasets.make_loan_panel(*, n_loans=5000, n_months=24, prepayment=0.0, correlation=0.0, factors=None, rng=None)#

生成分期贷款的合成月度面板数据。

贷款在 n_months 个月内陆续发放，并在每个账龄月的月末观测一次，直到最后一个放款月的下一个月。借款人漏缴期款时逾期向前滚动，还清欠款后回到正常；逾期达到 90 天的贷款会一直停留在该状态。数据是模拟生成的，并非取自真实的资产组合。

参数:
n_loansint，默认 5000

贷款笔数，每笔贷款随机分配到一个放款月。

n_monthsint，默认 24

放款月份数，从 2024 年 1 月开始。最早的批次观测 n_months 个账龄月，最晚的批次只观测一个。

prepaymentfloat，默认 0.0

正常贷款在最后一期到期之前一次还清全部余额的月度概率，取值为 0 到 1。默认值 0 不产生提前还款，给出的面板与以前的版本相同。

correlationfloat，默认 0.0

使所有贷款的还款每月一起变化的系统因子的资产相关系数，取值从 0 到小于 1，与 kivi.lifetime.conditional_matrix 相同。默认值 0 表示没有经济周期，得到与以前版本相同的面板。

factorsarray_like，可选

n_months 个月中每个月的标准正态系统因子取值，从 2024 年 2 月起；正值表示经济好于平均。默认情况下，若 correlation 为正，则从 rng 抽取这些因子。只能与为正的 correlation 一起使用。

rng{None, int, numpy.random.Generator}，可选

传给 numpy.random.default_rng 的种子或生成器。不使用 NumPy 的全局随机状态，因此同一个种子总是返回同样的面板数据。

返回值:
pandas.DataFrame

每笔贷款的每个账龄月一行，先按贷款、再按账龄排序。各列含义见“说明”。

异常:
ValueError

如果 n_loans 或 n_months 不是正整数， prepayment 不是 0 到 1 之间的数， correlation 不是从 0 到小于 1 的数， factors 在 correlation 不为正时给出或不是 n_months 个有限的数，或 rng 不是 numpy.random.default_rng 接受的种子或生成器。

参见

kivi.vintage.vintage_table

按批次和账龄统计的累计坏账率。

kivi.vintage.transition_matrix

贷款在逾期档位之间的迁移。

kivi.lifetime.survival_table

考虑提前还款的 PD 期限结构。

kivi.lifetime.matrix_correlation

由月度迁移估计因子的相关系数。

load_bank

带二分类目标的真实数据。

说明

各列为：

  • loan_id ：整数标识，随放款月份递增；

  • cohort ：放款月份，为月度 pandas.Period ；

  • month ：观测所在月份，即 cohort + month_on_book ；

  • month_on_book ：放款后经过的月数（账龄），从 1 开始；

  • term ：合同约定的月供期数，为 12、24 或 36；

  • amount ：放款金额；

  • balance ：月末的剩余本金；

  • status ：月末的逾期天数，为有序分类变量，类别依次为 current 、 1-29 、 30-59 、 60-89 和 90+ 。

每笔贷款按月等额本息还款，月利率为 1%。其状态记录自最早一期未还期款到期以来的月数：一个月为 1-29 ，两个月为 30-59 ，三个月为 60-89 ，四个月及以上为 90+ 。在期限内，这就是逾期未还的期数；期限结束后仍有欠款的贷款会继续滚动。

每个月，正常贷款漏缴当期期款的概率在放款后前六个月逐渐上升，之后下降，并乘以该贷款和所在批次各自的风险系数，因此不同批次的质量不同。逾期贷款要么还清全部欠款、回到正常，要么只还一期、保持原状态，要么完全不还、滚动到下一个逾期档位；逾期天数越长，回到正常的概率越低，滚动的概率越高。 90+ 的贷款不再还款，因此余额保持不变。贷款还清最后一期后离开面板；贷款不会被核销。

给出 prepayment 时，每个月，上月末为正常状态（每笔贷款在放款时都是如此）、且除本月到期的一期外还有剩余期数的贷款，以该概率一次还清全部余额，与其风险无关。该贷款当月余额为 0，此后不再有记录，因此期限之前余额为 0 表示提前还款，而按期还清的贷款在期限当月或之后余额才为 0。提前还款使用单独的随机数，在其他随机数全部抽取之后才抽取：在同一个 rng 下，每笔贷款在提前还款之前的路径都与不给 prepayment 时相同。

给出 correlation 时，还款取决于每个月的系统因子 \(z\) 。尚未逾期 90 天的贷款以概率 \(w\) 漏缴当期期款或没有还清全部欠款，以概率 \(v \le w\) 一分不还、滚动到下一个逾期档位。给定因子时，它们各自变为

\[\Phi\!\left(\frac{\Phi^{-1}(w) - \sqrt{\rho}\,z}{\sqrt{1 - \rho}}\right),\]

即 kivi.lifetime.conditional_matrix 的平移，因此对因子取平均时，每笔贷款保持原来的概率。因子使正常贷款的漏缴与逾期贷款的回到正常和滚动一起变化。默认抽取的因子排在所有其他随机数之后，也在 prepayment 的随机数之后。整个面板的月度迁移混合了不同风险和账龄的贷款，因此它们的矩阵随因子的变化只是近似于 conditional_matrix 给出的结果。

kivi.datasets.make_applications(*, n_applicants=10000, include_risk=False, rng=None)#

生成带审批决策的合成贷款申请数据。

每个申请人都有若干数值型和类别型特征、现行评分卡给出的 PD 以及真实的违约标记。现行评分卡的 PD 和两条政策规则决定谁获批，因此数据带有拒绝推断所要纠正的样本选择。数据是模拟的，并非取自真实的资产组合。

参数:
n_applicantsint，默认 10000

申请笔数。

include_riskbool，默认 False

如果为 True，则把隐藏风险因子作为最后一列 risk 附加到结果中。其他内容都不依赖它，因此同一个种子下，有无该列得到的申请数据是一样的。

rng{None, int, numpy.random.Generator}，可选

传给 numpy.random.default_rng 的种子或生成器。不使用 NumPy 的全局随机状态，因此同一个种子总是返回同样的申请数据。

返回值:
pandas.DataFrame

每笔申请一行，各列含义见“说明”。

异常:
ValueError

如果 n_applicants 不是正整数， include_risk 不是 True 或 False，或 rng 不是 numpy.random.default_rng 接受的种子或生成器。

参见

kivi.reject_inference.fuzzy_augmentation

推断拒绝申请人的结果。

make_loan_panel

贷款资产组合的合成月度历史。

make_transactions

合成的申请人账户交易流水。

load_bank

带二分类目标的真实数据。

说明

各列为：

  • age ：年龄（岁），从 18 到 75；

  • income ：月收入，取整到十位；

  • debt_to_income ：每月还债额与收入之比，保留两位小数；

  • inquiries ：近六个月的征信查询次数；

  • housing ：分类变量，类别为 own 、 mortgage 和 rent ；

  • employment ：分类变量，类别为 permanent 、 temporary 和 self_employed ；

  • incumbent_pd ：决定该申请的评分卡给出的 PD，保留四位小数；

  • policy_decline ：若某条政策规则拒绝了该申请（无论其 PD 如何）则为 True，规则为负债收入比高于 0.6 或年龄低于 21 岁；

  • approved ：若 incumbent_pd 低于 0.15 且没有政策规则拒绝该申请，则为 True；

  • target ：申请人违约为 1，否则为 0；

  • risk ：仅在 include_risk=True 时给出，为隐藏风险因子，是不取整的标准正态抽样值。

违约概率随负债收入比和征信查询次数上升，随年龄和收入下降，租房者以及临时雇佣和自雇的申请人违约概率更高。除非 include_risk 为 True，否则不在任何列中的隐藏风险因子也会提高违约概率，征信查询次数也随该因子增加。

现行评分卡对各特征的权重不同，不使用 housing ，并且像手握征信报告的审批人员一样，能看到隐藏风险因子的一部分。因此，在特征相同时，拒绝申请人比获批申请人风险更高，只用获批申请人拟合的模型会低估他们的违约率。

实际中只有获批申请人的结果是已知的。这里也给出了拒绝申请人的 target ，但只用于评估拒绝推断：不能用它拟合模型，否则拒绝推断就失去了意义。 risk 也是如此：它是任何数据集中都没有的信息，只是为了模拟依赖于它的数据而给出，如 make_transactions 所做的那样。

示例

>>> from kivi.datasets import make_applications
>>> applications = make_applications(rng=0)
>>> applications.shape
(10000, 10)

拒绝申请人的违约频率是获批申请人的三倍，这只有合成数据才能展示：

>>> by_decision = applications.groupby(["policy_decline", "approved"])["target"]
>>> by_decision.agg(["size", "mean"]).round(3)
                         size   mean
policy_decline approved
False          False     2467  0.301
               True      6770  0.097
True           False      763  0.274
kivi.datasets.make_transactions(applications, *, application_date, n_months=12, rng=None)#

生成申请日期之前的合成账户交易流水。

每位申请人在申请前的 n_months 个月中，每个月都有账户交易：银行卡消费、取现和分期还款。这些交易取决于申请人的隐藏风险因子和收入，而不取决于结果。处于风险中的申请人会累积压力，在临近申请时取现更多、还款更少，交易金额随收入增长，因此按时间窗计算的交易流水特征对 target 有清晰但不完美的信号。数据是模拟的，并非取自真实的资产组合。

参数:
applicationspandas.DataFrame

每个申请人一行，包含 kivi.datasets.make_applications 在 include_risk=True 时给出的 income 、 debt_to_income 、 incumbent_pd 和 risk 列，且索引标签唯一。其他列（包括 target ）会被忽略。

application_date{str, date, array_like}

每个申请的日期。若字符串是 applications 的某一列名，则从该列读取日期。其他字符串、 datetime.date 、 numpy.datetime64 或 pandas.Timestamp 表示所有申请共用的同一个日期。与 applications 索引相同的 Series，或每行一个日期的 array_like，则为每个申请指定各自的日期。日期按 pandas.to_datetime 的方式读取，与 kivi.vintage.delinquency_panel 一致：时间部分会被忽略，时区会被去掉，数字和 Period 会报错，因此请先用 .dt.to_timestamp() 转换 Period 列。

n_monthsint，默认 12

交易覆盖申请日期之前的月数。申请人的交易落在申请日期之前 n_months 个日历月的起点（按 pandas.DateOffset 的方式计算）到申请日期之间，含起点，不含申请日期本身。

rng{None, int, numpy.random.Generator}，可选

传给 numpy.random.default_rng 的种子或生成器。不使用 NumPy 的全局随机状态，因此同一个种子总是返回同样的交易流水。

返回值:
pandas.DataFrame

每笔交易一行，先按申请人（顺序同 applications ）、再按时间排序，索引为 RangeIndex，各列含义见“说明”。

异常:
ValueError

若 applications 不是 DataFrame、缺少必需的列（缺少 risk 时，报错信息会点出 include_risk ）、索引标签重复或不是单层索引，或必需列中有缺失值、非数值或超出范围的值。若 application_date 既不是列名、日期，也不是每个申请一个值的日期序列，含缺失值，或是索引与 applications 不同的 Series。若 n_months 不是正整数或会追溯到 1678 年之前，或者 rng 不是 numpy.random.default_rng 接受的种子或生成器。

参见

make_applications

带审批决策的合成贷款申请数据。

make_loan_panel

贷款资产组合的合成月度历史。

说明

结果的列为：

  • applicant_id ：申请人在 applications 中的索引标签；

  • timestamp ：交易发生的时间，精确到秒，落在申请日期之前；

  • amount ：金额，为正，保留两位小数；

  • kind ：分类变量，类别为 purchase 、 cash_withdrawal 和 repayment ；

  • merchant_category ：分类变量，有八个类别，例如 grocery 和 travel ，用于消费交易，其他类型的交易为缺失。

各月的交易相互独立地生成。一年中，申请人平均约有 25 笔消费、8 笔取现和 11 笔还款，共 44 笔交易。一笔消费约为月收入的 4.5%，一笔取现约为 3%，还款则是 income * debt_to_income 对应的分期款，各申请人之间相差约 20%。 income 较高的申请人消费和取现略多一些，起始于 11 月和 12 月的月份消费更频繁。现行评分卡评为风险较高的申请人取现更多、漏还也更多， risk 较高的申请人也是如此。

risk 还会带动一种在申请前逐步累积的压力。它在申请前三到九个月开始，在最后一个月最强。压力水平随风险加噪声而上升，从几乎没有到一个有界的最大值。受压时，取现更频繁、金额更大，消费略有减少，还款更可能漏还，或少还至多一成。因此最近几个月的取现次数和金额、还款笔数，以及还款金额相对此前几个月的变化，对 risk 有信号，并通过它对 target 有信号，因为同一个风险也会提高违约概率。现行评分卡只看到风险的一部分，所以在 incumbent_pd 的各个分段内，信号依然存在。噪声以及申请人之间的其他差异，使任何特征都远不是完美的预测变量。

交易流水不取决于 target ：它们是在结果产生之前根据风险生成的，就像贷款人观察到的那样。 risk 是任何贷款人都没有的信息，因此只存在于模拟的申请数据中。

时间窗所截止的观察表，每个申请一行并带有申请日期，可以由申请数据及其日期得到，示例中有说明。

示例

>>> import numpy as np
>>> import pandas as pd
>>> from kivi.datasets import make_applications, make_transactions
>>> applications = make_applications(n_applicants=1000, include_risk=True, rng=0)
>>> days = np.arange(1000) * 366 // 1000
>>> applications["application_date"] = pd.Timestamp("2024-01-01") + pd.to_timedelta(
...     days, unit="D"
... )
>>> transactions = make_transactions(
...     applications, application_date="application_date", rng=0
... )
>>> list(transactions.columns)
['applicant_id', 'timestamp', 'amount', 'kind', 'merchant_category']

观察表每个申请一行，含申请人 ID 和日期，其索引与申请数据相同，为它们算出的特征可以据此拼回申请数据：

>>> observations = pd.DataFrame(
...     {
...         "applicant_id": applications.index,
...         "application_date": applications["application_date"],
...     },
...     index=applications.index,
... )
>>> observations.head(2)
   applicant_id application_date
0             0       2024-01-01
1             1       2024-01-01

日期也可以是所有申请共用的同一个日期，或与申请数据索引相同的 Series：

>>> transactions = make_transactions(
...     applications, application_date="2024-06-30", n_months=6, rng=0

kivi.datasets.make_defaults(*, n_defaults=2000, rng=None)#

生成带违约风险敞口和清收信息的合成违约贷款。

每笔贷款都在 2018 年至 2024 年间违约，分为有抵押贷款、无抵押贷款和循环额度三类。表中包含贷款机构在违约时所知道的贷款信息、循环额度在违约前 12 个月的额度和已提用金额，以及清收结束的日期（若在数据截止日 2025 年 6 月 30 日之前结束）。 kivi.datasets.make_recoveries 模拟这些清收过程的现金流。数据是模拟生成的，并非取自真实的资产组合。

参数:
n_defaultsint，默认 2000

违约贷款的笔数。

rng{None, int, numpy.random.Generator}，可选

传给 numpy.random.default_rng 的种子或生成器。不使用 NumPy 的全局随机状态，因此同一个种子总是返回同样的贷款。

返回值:
pandas.DataFrame

每笔违约贷款一行，按违约日期排序，索引为 RangeIndex，各列含义见“说明”。

异常:
ValueError

如果 n_defaults 不是正整数，或 rng 不是 numpy.random.default_rng 接受的种子或生成器。

参见

make_recoveries

这些贷款清收过程的合成现金流。

make_loan_panel

贷款资产组合的合成月度历史。

说明

各列为：

  • loan_id ：整数标识，从 1 开始，随违约日期递增；

  • segment ：分类变量，类别为 secured 、 unsecured 和 revolving ，分别约占贷款的 40%、35% 和 25%；

  • default_date ：违约日期，从 2018 年到 2024 年；

  • ead ：违约风险敞口，即违约当日的未偿金额，保留到分；

  • limit ：循环额度在违约前 12 个月（即 CCF 的参考日）的额度，取整到百位；其他分段为缺失值；

  • drawn ：循环额度在参考日的已提用金额，保留到分；其他分段为缺失值；

  • collateral_value ：有抵押贷款在违约时的抵押品价值，取整到百位；其他分段为 0；

  • discount_rate ：把清收现金流折现到违约日的年折现率，为违约当月的模拟三个月货币市场利率加 5 个百分点，符合 EBA/GL/2017/16 第 143 段的规定；

  • closing_date ：清收结束的日期，即治愈、处置抵押品或核销未回收部分的日期；在数据截止日 2025 年 6 月 30 日仍未结案的清收为缺失值。

一次清收至少持续三个月，即治愈的观察期。约 30% 的有抵押贷款、10% 的无抵押贷款和 15% 的循环额度会治愈，平均用时七个月。处置的平均时长，有抵押贷款约为两年半，无抵押贷款约为一年半，循环额度约为 15 个月，因此最近几年开始的清收有许多在截止日仍未结案。

有抵押贷款的违约风险敞口中位数为 120,000，违约时贷款价值比的中位数为 75%，有些贷款的欠款高于其抵押品的价值；无抵押贷款的违约风险敞口中位数为 12,000。循环额度的额度中位数为 6,000，在参考日的使用率约为 60%，另有 3% 恰好用满额度，3% 超出额度。之后，多数额度在违约前又提用了一部分剩余额度，10% 偿还了部分余额，10% 在违约时超出额度，因此实际 CCF (ead - drawn) / (limit - drawn) 大多在 0 到 1 之间，也有一些低于 0 或高于 1；用满额度的循环额度没有定义 CCF。

kivi.datasets.make_recoveries(defaults, *, rng=None)#

生成违约贷款清收过程的合成现金流。

defaults 中的每笔贷款都会得到其清收过程中的回收、费用和治愈现金流，时间从违约日到结案日；仍未结案的清收则到数据截止日 2025 年 6 月 30 日为止。有抵押贷款大多通过处置抵押品收回敞口，无抵押贷款和循环额度收回的很少，治愈的贷款则全部收回，因此实际 LGD 呈双峰分布。数据是模拟生成的，并非取自真实的资产组合。

参数:
defaultspandas.DataFrame

每笔违约贷款一行，包含 kivi.datasets.make_defaults 的 loan_id 、 segment 、 default_date 、 ead 、 collateral_value 和 closing_date 列。日期列必须为 datetime64 类型，一天中的时间会被忽略。其他列会被忽略。

rng{None, int, numpy.random.Generator}，可选

传给 numpy.random.default_rng 的种子或生成器。不使用 NumPy 的全局随机状态，因此同一个种子总是返回同样的现金流。

返回值:
pandas.DataFrame

每笔现金流一行，先按贷款（顺序同 defaults ）、再按日期排序，索引为 RangeIndex，各列含义见“说明”。

异常:
ValueError

如果 defaults 不是 DataFrame，缺少某个必需的列或有两个同名的列， loan_id 有缺失或重复， segment 不是 secured 、 unsecured 或 revolving ， ead 不是有限正数， collateral_value 不是有限非负数，日期列不是 datetime64 类型， default_date 有缺失、早于 1678 年或晚于截止日，或 closing_date 早于 default_date 或晚于截止日。如果 rng 不是 numpy.random.default_rng 接受的种子或生成器。

参见

make_defaults

带违约风险敞口和清收信息的合成违约贷款。

kivi.calibration.backtest_table

用实际 LGD 回测 LGD 估计值。

说明

结果的列为：

  • loan_id ：贷款在 defaults 中的 loan_id ；

  • date ：现金流的日期；

  • amount ：金额，保留到分；回收和治愈为正，费用为负；

  • kind ：分类变量，类别为 recovery 、 cost 和 cure 。

cure 是已治愈贷款在结案日的未偿金额，EBA/GL/2017/16 第 135 段将其视为借款人在当日偿还了这笔金额。贷款的实际 LGD 为 (ead + PV(costs) - PV(recoveries)) / ead ，其中回收包括治愈，现值把现金流折现到违约日。用 make_defaults 的 discount_rate 折现时，多数有抵押贷款和已治愈贷款的实际 LGD 接近 0；未治愈的无抵押贷款和循环额度接近 1；少数有抵押贷款的抵押品覆盖了含罚息的债权，其 LGD 低于 0；少数贷款的费用超过回收，其 LGD 高于 1。

清收过程只通过其时长依赖于 defaults 中的日期，时长越短，越可能是治愈：

  • 已治愈的贷款在清收期间偿还部分欠款，有时产生少量费用，并在结案日治愈；

  • 未治愈的有抵押贷款在清收期间偿还少量款项，并在结案日处置抵押品。银行在其债权（违约风险敞口加上年利率 4% 到 10% 的罚息）范围内收回处置所得，并支付处置所得 3% 的处置费用和若干法律费用；

  • 未治愈的无抵押贷款或循环额度平均分别收回其违约风险敞口的约 17% 或 22%，分多笔收回，并产生若干催收费用。

约 5% 的贷款在违约前 90 天内有一笔法律费用，EBA/GL/2017/16 第 144 段把它计入经济损失；3% 的处置有占违约风险敞口 10% 到 40% 的诉讼费用。在截止日仍未结案的清收只有截止日之前的现金流，之后没有，因此其迄今为止的 LGD 高估了它最终实现的 LGD。
