分箱方案#

一步完成数据框所有列的分箱和编码。 fit_spec() 拟合每一列的分箱和 WOE，得到的 BinningSpec 以同样的方式对其他任何样本分组和编码，并能保存为带版本号的 JSON。

示例和文件格式见 分箱方案 。

fit_spec(frame, target, *[, columns, ...])

在开发样本上拟合每一列的分箱和 WOE。

BinningSpec(kinds, edges, special, tables, ...)

在开发样本上拟合的、每一列的分箱和 WOE 编码。
kivi.spec.fit_spec(frame, target, *, columns=None, method='quantile', bins=5, special=None, options=None, unseen='raise', smoothing=0.5, weights=None)#

在开发样本上拟合每一列的分箱和 WOE。

数值列按为其选定的方法分箱，并用 kivi.binning.cut 分组。 method 中指定的类别列用 kivi.binning.category_groups 或 kivi.binning.chimerge_groups 以及 kivi.binning.group_categories 分组；其他类别列以自身标签作为分组。然后用 kivi.woe.woe_table 计算每个分组的 WOE。不会自动重新分箱：每一列分箱的粗细由其方法、箱数和选项决定。

参数:
framepandas.DataFrame

开发样本，每个变量一列。数值 dtype（bool 除外）的列会被分箱。其他 dtype 的列（例如 object、string、category 或 bool）是类别列：除非 method 对该列分组，否则每个标签是一个分组。若要把整数编码当作标签，请先将其转换为 category dtype。

targetarray_like

二分类标签，1 表示事件， frame 的每一行一个。Series 必须与 frame 的索引相同；其他输入按位置对应。

columnsstr 序列，可选

要拟合的列，其顺序即分箱方案中的顺序。默认为 frame 的所有列。

methodstr 或 dict，默认 "quantile"

数值列的分箱方法： "quantile" 或 "uniform" 对应 kivi.binning.bin_edges ， "chimerge" 、 "tree" 或 "monotonic" 分别对应 kivi.binning.chimerge_edges 、 kivi.binning.tree_edges 和 kivi.binning.monotonic_edges 。dict 把列映射到方法，dict 中未列出的数值列使用 "quantile" 。dict 也可以对类别列分组： "rare" 对应 kivi.binning.category_groups ， "chimerge" 对应 kivi.binning.chimerge_groups ；dict 中未列出的类别列保留其标签。

binsint 或 dict，默认 5

箱数，作为 bins 传给 kivi.binning.bin_edges ，作为 max_bins 传给有监督方法，作为 max_groups 传给 kivi.binning.chimerge_groups 。dict 把列映射到箱数或边界；边界必须从 -inf 递增到 inf ，并按原样使用。对 "monotonic" ，None 表示只合并到 WOE 单调为止。dict 中未列出的数值列和 "chimerge" 列分为 5 箱。用 "rare" 分组的列不接受箱数。

specialdict，可选

数值列和已分组类别列的特殊值编码，例如 {"pdays": [-1], "job": ["unknown"]} 。数值列的编码必须是数值，可以是无穷；类别列的编码是标签。拟合时排除这些编码，每个编码单独成组。

optionsdict，可选

传给每一列分箱或分组函数的其他关键字参数，例如配合 "chimerge" 使用的 {"balance": {"alpha": None}} ，或配合 "rare" 使用的 {"job": {"min_share": 0.02}} 。特殊值、权重、箱数，以及 "monotonic" 和用 "chimerge" 分组时的平滑参数，由 fit_spec 传入，不能在这里指定。

unseenfloat、"raise" 或 dict，默认 "raise"

编码样本时，分组不在该列 WOE 表中的取值所用的 WOE：新类别、开发样本中没有观测值的特殊值或区间，或开发样本没有缺失值时的缺失值。默认情况下，这类取值会引发错误。dict 把列映射到 WOE 或 "raise" ，dict 中未列出的列会引发错误。对已分组的列， {"group": label} 让这类取值改用该组的 WOE，并且 BinningSpec.cut 会把新类别分配到该组；该组必须在拟合得到的 WOE 表中。

smoothingfloat，默认 0.5

计算 WOE 时用这个正数替代零计数，含义与 kivi.woe.woe_table 相同。 "monotonic" 分箱使用同一取值，因此其单调趋势在 WOE 表中同样成立。

weightsarray_like，可选

每一行的非负权重，对应方式与 target 相同，会传给分箱函数和 kivi.woe.woe_table 。此时计数为权重之和， smoothing 也以权重为单位。

返回值:
BinningSpec

每一列的类型、边界、特殊值、分组映射、WOE 表和未见分组策略。

异常:
ValueError

如果 frame 不是 DataFrame 或没有可拟合的列， columns 重复某一列或指定了 frame 中没有的列，列名不是字符串，拟合的列包含目标变量，或 target 的标签不是每行一个 0 或 1，或者缺少两类中的一类。如果某个 dict 指定了未拟合的列， method 为类别列指定了 "chimerge" 或 "rare" 以外的方法， bins 、 special 或 options 指定了 method 未分组的类别列，或某个取值无效，例如数值列的特殊值编码不是数值。此外，如果 smoothing 或 weights 无效，某个数值列含有不属于特殊值的无穷值，或某一列分箱或分组失败；此时错误信息会指明该列。

警告:
UserWarning

如果重合的分位数使某一列的箱数少于期望值（与 kivi.binning.bin_edges 相同），某个数值列除缺失值、特殊值和零权重的取值外没有可拟合的值，从而其边界为 [-inf, inf] ，某个已分组的列没有这样的值，从而其分组只有特殊值，或者某个 object dtype 的列只含数值，使每个不同的数值各成一组。警告信息会指明该列。

参见

BinningSpec

对拟合好的列分组、编码并保存。

kivi.binning.bin_edges

拟合单列的边界。

kivi.binning.chimerge_groups

对单列的类别分组。

kivi.woe.woe_table

单列的 WOE 表。

说明

每一列都用公开函数单独拟合，因此分箱方案中某一列的边界和 WOE 表，与单独对该列执行 分箱 和 证据权重与信息值 中的步骤所得的结果相同。

示例

>>> import pandas as pd
>>> from kivi.spec import fit_spec
>>> frame = pd.DataFrame({
...     "age": [23, 31, 45, 52, 38, 27, 61, 49],
...     "housing": ["yes", "no", "yes", "no", "no", "yes", "no", "yes"],
... })
>>> target = pd.Series([1, 0, 0, 0, 1, 1, 0, 0])
>>> spec = fit_spec(frame, target, bins=2)
>>> spec.tables["age"][["non_event", "event", "woe"]].round(4)
              non_event  event     woe
bin
(-inf, 41.5]          1      3  1.4553
(41.5, inf]           4      0 -1.7228
>>> spec.woe_transform(frame).head(3).round(4)
      age  housing
0  1.4553   0.5108
1  1.4553  -0.5878
2 -1.7228   0.5108
class kivi.spec.BinningSpec(kinds, edges, special, tables, unseen, smoothing=0.5, kivi_version=None, groups=None)#

在开发样本上拟合的、每一列的分箱和 WOE 编码。

对每一列，分箱方案记录：它是数值列还是类别列、数值列的边界和特殊值、已分组类别列的分组映射、其各分组的 WOE 表，以及不在表中的分组的处理策略。 cut 用同样的边界和分组映射对任意样本分组， woe_transform 用同样的 WOE 编码， to_json 和 from_json 保存并加载分箱方案，且不会改变分组和编码。请用 fit_spec 拟合分箱方案，而不是直接调用构造函数。

分箱方案不可变。其映射是只读的， edges 、 groups 和 tables 每次访问都返回数组、dict 或表的新副本，因此修改副本不会影响分箱方案。若要修改某个字段（例如未见分组策略），请使用 dataclasses.replace ，它会重新校验结果。

参数:
kindsmapping

每一列为 "numeric" 或 "categorical" ，顺序即分箱方案中的顺序。

edgesmapping

每个数值列的边界，从 -inf 递增到 inf 。

specialmapping

每个数值列的特殊值，可以为空。这些编码是数值，与 kivi.binning.cut 相同，每个编码单独成组。

tablesmapping

每一列的 kivi.woe.woe_table 结果。数值列的分组是其特殊值和由边界构成的区间，已分组列的分组是其分组映射中的各组。缺失值单独成组，标签为 NaN。

unseenmapping

每列的 "raise" 或有限的 WOE，用于分组不在该列 WOE 表中的取值。已分组的列也可以用 {"group": label} 指定其中一个组：这类取值改用该组的 WOE，并且 cut 会把分组映射中没有的类别分配到该组。

smoothingfloat，默认 0.5

计算 WOE 表时所用的平滑参数。

kivi_versionstr，可选

拟合该分箱方案的 kivi 版本。默认或为 None 时取已安装的版本。

groupsmapping，可选

每个已分组类别列的分组映射：从类别到组的 dict，与 kivi.binning.category_groups 或 kivi.binning.chimerge_groups 的返回值相同。没有对应项的类别列以自身标签作为分组。默认不对任何列分组。

属性:
FORMAT_VERSIONint

JSON 格式的最新版本， from_json 能读取该版本，含已分组列的分箱方案由 to_json 按该版本写出。

异常:
ValueError

如果 kinds 为空、含有非字符串的列名或上述两种以外的类型；如果 edges 和 special 不是每个数值列恰好一项， groups 含有非类别列的项，或 tables 和 unseen 不是每列恰好一项；或某一项无效：边界没有从 -inf 递增到 inf 、特殊值缺失或类型不受支持、分组映射含有缺失或类型不受支持的类别或组、WOE 表没有有限的 woe 列或有重复分组、数值列的某个分组既不是其特殊值也不是其边界构成的区间、已分组列的某个分组不在其分组映射中，或未见分组策略既不是 "raise" 也不是有限数值，对已分组的列也不是其 WOE 表中的组。此外，如果 smoothing 不是有限正数，或 kivi_version 不是字符串。

参见

fit_spec

在开发样本上拟合分箱方案。

kivi.binning.cut

对单个数值列分组。

kivi.woe.woe_transform

用单列的 WOE 表对该列编码。

说明

类别列的标签必须是字符串、整数、浮点数、布尔值或区间，JSON 格式会区分这些类型。在同一列中，相等的标签（例如 True 和 1 ）属于同一分组，因为 kivi.woe.woe_table 和 kivi.woe.woe_transform 按相等关系匹配标签。分组映射中的类别和组同样如此；分组映射会把同一组的类别放在一起，并按各组首次出现的次序排列。

当 to_json 为两个分箱方案给出相同的文本时，二者相等；文本中包含 kivi_version 。文本只计算一次并保留下来，因此再次比较或计算哈希的开销很小。

示例

>>> import pandas as pd
>>> from kivi.spec import fit_spec
>>> frame = pd.DataFrame({
...     "age": [23, 31, 45, 52, 38, 27, 61, 49],
...     "housing": ["yes", "no", "yes", "no", "no", "yes", "no", "yes"],
... })
>>> target = pd.Series([1, 0, 0, 0, 1, 1, 0, 0])
>>> spec = fit_spec(frame, target, bins=2)
>>> spec
BinningSpec(columns=['age', 'housing'])
>>> dict(spec.kinds)
{'age': 'numeric', 'housing': 'categorical'}
>>> spec.edges["age"]
array([-inf, 41.5,  inf])

cut(frame)#

按开发时的方式对样本的每一列分组。

数值列用 kivi.binning.cut 按拟合的边界和特殊值分箱。已分组的类别列按 kivi.binning.group_categories 的方式分配到各组。分组映射中没有的类别归入该列未见分组策略指定的组；若没有指定，则保留自身标签，这样 kivi.stability.psi_table 会把它显示为一个新组。其他类别列原样返回，因为其标签就是分组。

参数:
framepandas.DataFrame

包含分箱方案中所有列的样本。其他列会被忽略。

返回值:
pandas.DataFrame

分箱方案中每一列的分组，按分箱方案的顺序排列，索引与 frame 相同。数值列为分类型，类别依次为特殊值和由边界构成的全部区间。已分组列为分类型，类别依次为按分组映射顺序排列的各组，以及分组映射中没有、也没有归入未见分组的类别。

异常:
ValueError

如果 frame 不是 DataFrame、缺少分箱方案中的某一列或该列出现两次，或者按数值列拟合的某一列有取值但不是数值 dtype，这可能使其特殊值无法匹配；请用 pandas.to_numeric 转换这样的列。此外，如果没有指定未见分组的已分组列含有分组映射中没有、却与其某个组的标签相同的类别，其分组就会含糊不清，也会引发错误。错误信息会指明该列。

参见

woe_transform

用拟合的 WOE 对分组编码。

kivi.binning.cut

对单个数值列分组。

kivi.binning.group_categories

对单个类别列分组。

示例

>>> import pandas as pd
>>> from kivi.spec import fit_spec
>>> frame = pd.DataFrame({"age": [23, 31, 45, 52], "housing": ["yes", "no", "yes", "no"]})
>>> spec = fit_spec(frame, [1, 0, 0, 1], bins=2)
>>> spec.cut(pd.DataFrame({"age": [30, 70], "housing": ["no", "yes"]}))
            age housing
0  (-inf, 38.0]      no
1   (38.0, inf]     yes
woe_transform(frame)#

用开发时拟合的 WOE 对样本的每一列编码。

各列先按 cut 的方式分组，再由 kivi.woe.woe_transform 把每个分组替换为其 WOE。不在该列 WOE 表中的分组（例如新类别）按该列的未见分组策略处理，默认会引发错误。已分组列中分组映射没有的类别也按此处理，即使它与某个组的标签相同（此时 cut 会引发错误）。指定了未见分组时，这类取值使用该组的 WOE。

参数:
framepandas.DataFrame

包含分箱方案中所有列的样本。其他列会被忽略。

返回值:
pandas.DataFrame

分箱方案中每一列的浮点 WOE 值，按分箱方案的顺序排列，索引与 frame 相同。

异常:
ValueError

如果 frame 不是 DataFrame、缺少分箱方案中的某一列或该列出现两次，按数值列拟合的某一列有取值但不是数值 dtype，或者未见分组策略为 "raise" 的列含有分组不在其 WOE 表中的取值，或（对已分组的列而言）类别不在其分组映射中的取值。错误信息会指明该列。

参见

cut

只对各列分组，不编码。

kivi.woe.woe_transform

对单列编码。

kivi.scorecard.woe_to_points

把 WOE 值转换为分值。

说明

由边界构成的区间为左开右闭，因此 -inf 不落入任何区间。 cut 与 pandas.cut 一样把它留为缺失值，而 woe_transform 把它视为未见分组，而不是赋予缺失组的 WOE。

示例

>>> import pandas as pd
>>> from kivi.spec import fit_spec
>>> frame = pd.DataFrame({
...     "age": [23, 31, 45, 52, 38, 27, 61, 49],
...     "housing": ["yes", "no", "yes", "no", "no", "yes", "no", "yes"],
... })
>>> target = pd.Series([1, 0, 0, 0, 1, 1, 0, 0])
>>> new = pd.DataFrame({"age": [30, 70], "housing": ["no", "rent"]})
>>> fit_spec(frame, target, bins=2).woe_transform(new)
Traceback (most recent call last):
...
ValueError: column 'housing': 1 group(s) are not in table, such as 'rent'; ...

为 housing 指定未见分组的 WOE 后，新标签得到 0：

>>> spec = fit_spec(frame, target, bins=2, unseen={"housing": 0.0})
>>> spec.woe_transform(new).round(4)
      age  housing
0  1.4553  -0.5878
1 -1.7228   0.0000

to_dict()#

返回值:
dict

包含键 format 、 format_version 、 kivi_version 、 smoothing 和 variables ；后者是每列一个 dict 的列表。格式说明见用户指南。

to_json(*, indent=None)#

以 JSON 文本返回分箱方案。

该文本就是由 json.dumps 写出的 to_dict 的 dict。同一个分箱方案总是得到相同的文本，因此保存的分箱方案可以相互比较，并纳入版本控制。非 ASCII 标签按原样写出，因此请以 UTF-8 保存文本。

参数:
indentint，可选

嵌套值的缩进，含义与 json.dumps 相同。默认文本只有一行。

返回值:
str

JSON 文本， from_json 可将其读回为相等的分箱方案。

参见

from_json

读回分箱方案。

to_dict

以 dict 表示的相同内容。

示例

>>> import pandas as pd
>>> from kivi.spec import fit_spec
>>> frame = pd.DataFrame({"age": [23, 31, 45, 52]})
>>> spec = fit_spec(frame, [1, 0, 0, 1], bins=2)
>>> print(spec.to_json(indent=2))
{
  "format": "kivi.BinningSpec",
  "format_version": 1,
  "kivi_version": "...",
  "smoothing": 0.5,
  "variables": [
    {
      "name": "age",
      "kind": "numeric",
      "edges": [
        {
          "float": "-inf"
        },
        38.0,
...

用 Path("spec.json").write_text(text, encoding="utf-8") 把文本写入文件。

classmethod from_json(text)#

从 to_json 写出的 JSON 文本读取分箱方案。

加载的分箱方案对每个样本的分组和编码，与保存时的分箱方案完全相同。由更新版本格式写出的文件会被拒绝，而不会只读取其中一部分。

参数:
textstr 或 bytes

JSON 文本，例如来自 Path(...).read_text(encoding="utf-8") 。

返回值:
BinningSpec

分箱方案，与写出 text 的那个相等。

异常:
ValueError

如果 text 既不是 str 也不是 bytes、不是有效的 JSON、含有 NaN 或 Infinity ，或没有描述一个有效的分箱方案；参见 from_dict 。

参见

to_json

写出分箱方案。

from_dict

由 dict 重建分箱方案。

示例

>>> import pandas as pd
>>> from kivi.spec import BinningSpec, fit_spec
>>> frame = pd.DataFrame({"age": [23, 31, 45, 52]})
>>> spec = fit_spec(frame, [1, 0, 0, 1], bins=2)
>>> loaded = BinningSpec.from_json(spec.to_json())
>>> loaded == spec
True
>>> loaded.woe_transform(frame).equals(spec.woe_transform(frame))
True
