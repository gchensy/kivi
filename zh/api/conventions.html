约定#

kivi 的每个公共函数都遵守本页的规则。模块页面和各篇指南默认这些规则成立，docstring 只说明某个函数与之不同或在其之外补充的地方。

导入#

kivi 没有顶层导入。请从各自所在的模块导入函数，例如 from kivi.woe import woe_table ；每个模块在本参考中都有自己的页面。

只有模块在 __all__ 中列出的名称是公共的。 兼容性 说明版本可以改变其中哪些名称，以及如何预先公布这种改变。

kivi 只依赖 NumPy 和 pandas。 kivi.plotting 还需要 matplotlib，可通过 plot 附加依赖安装（ pip install "kivi[plot]" ）；它只在绘图时才导入 matplotlib，因此导入 kivi 从不需要 matplotlib。

参数#

  • 数据在前，目标变量在数据之后，例如 woe_table(groups, target) 、 roc_auc(score, target) 、 stepwise(X, target) 和 fit_spec(frame, target) 。有多个数据参数的函数先接收全部数据参数，再接收目标变量，例如 swap_set(current, new, target) ；预测概率放在目标变量之后，例如 calibration_table(groups, target, probability) 。连续型估计值的回测遵循同样的顺序，实际值处于目标变量的位置，估计值处于概率的位置，例如 backtest_table(groups, realized, estimated) ； generalized_auc() 则像对待评分一样把估计分段作为数据，把实际分段作为目标，例如 generalized_auc(estimated, realized) 。scikit-learn 的指标函数把目标变量放在前面，从那里移植代码时请检查参数顺序。

  • 描述其他观测的数据（例如被拒绝的申请人）位于主样本的数据和目标变量之后，例如 parceling(score, target, reject_score) ，以及没有目标变量的 reweighting(score, reject_score) 。同样， delinquency_panel() 的还款记录位于其还款计划之后，例如 delinquency_panel(loan, due_date, amount_due, payment_loan, payment_date, payment_amount) ； workout_lgd() 的现金流位于其违约贷款之后，例如 workout_lgd(loan, default_date, ead, flow_loan, flow_date, flow_amount, rate=rate) ，回收为正，费用为负。

  • kivi.features 的函数与 fit_spec() 和 profile_table() 一样接受带列名的表：先是事件表或月度面板，然后是 observations ，每个主体和观察时间一行，例如申请人及其申请日期，如 window_features(events, observations, id=..., time=..., observation_time=...) 。列名以关键字参数给出。 id 在两张表中指明主体，其取值按相等匹配，因此 1 和 "1" 是不同的主体。

  • X 是数值型模型矩阵，例如 stepwise() 、 logistic_regression() 、 selection_path() 、 vif() 、 vif_filter() 、 correlation_filter() 和 fractional_regression() 中的 X 。 fractional_regression() 的 response 是 0 到 1 之间的连续目标，例如实际 LGD；二元目标则称为 target 。 frame 包含原始列，例如 fit_spec() 、 profile_table() 、 rule_candidates() 和 BinningSpec.cut 中的 frame ； woe 是 woe_to_points() 转换为分数的 WOE 值矩阵。

  • rules 是 kivi.rules 中由政策规则组成的 DataFrame，每条规则一列，以规则命名，每个申请人一行，例如 rule_table(rules, target) 。每列为布尔值或 0 和 1，规则命中（即拒绝或标记该申请人）处为 True。 rule_set_table() 按列的顺序应用这些规则。

  • 在 kivi.expert 中， matrix 是两两比较的方阵：可以是索引和列以相同顺序给出相同因子标签的 DataFrame，也可以是数组或嵌套列表，此时因子从 0 起编号。其对角线必须为 1，元素必须互为倒数，即 \(a_{ij} a_{ji} = 1\) ，满足关键字参数 rtol 给出的相对容差，默认 1e-3，可以接受四舍五入到四位小数的倒数，例如用 0.3333 表示 1 / 3。 transition_pd() 的 matrix 则是转移矩阵，每行是总和为 1 的概率。

  • 在 migration_bandwidth() 和 migration_test() 中， grades 按从最好到最差的顺序列出评级体系的等级，至少两个。这两个函数像 transition_matrix() 一样，接收每个客户在期初的等级和期末的状态，例如 migration_test(before, after, grades=grades) 。 before 的每个值都必须是等级；期末状态不是等级的客户（例如 "default" 或 "closed" ）只计入其期初等级的客户数。

  • realized 和 estimated 是连续值，例如一笔已结案违约的实际 LGD 及其估计值，可以落在 [0, 1] 之外。对 generalized_auc() 而言，它们是有序的分段：数值按大小排序，有序分类变量按类别顺序排序。

  • 事件的预测概率（例如 PD）一律称为 probability ，例如 brier_score(probability, target) 、 calibration_table(groups, target, probability) 和 expected_loss(probability, lgd, ead) 。 score 的含义因模块而异，见 目标变量、评分与概率 。第二个概率参数按其含义命名，例如 significant_increase() 中的 origination_probability 。

  • 含义相同的选项在各个模块中同名，例如 bins 、 special 、 smoothing 、 unseen 和 weights 。 level 是区间或上界的置信水平，为严格介于 0 和 1 之间的数，默认 0.95，例如 roc_auc_interval() 、 generalized_auc() 和 most_prudent_pd() 。 capital_requirement() 的 level 是单因子模型的置信水平，按内部评级法的规定默认 0.999； conditional_pd() 的 level 则是经济状况的分位数，用来代替 factor 。

  • 对变量分箱时 bins 默认为 5，例如 bin_edges() 、 fit_spec() 和 profile_table() ；对评分划分区段时默认为 10，例如 gains_table() 、 monitoring_table() 、 parceling() 和 reweighting() 。 cutoff_table() 和 confusion_table() 的 cutoffs 同样默认为 10 个区段。

  • asset_class 选择 kivi.capital 的风险权重函数： "corporate" 、 "hvcre" 、 "mortgage" 、 "revolving" 或 "other_retail" 。它只能以关键字传入且没有默认值，因为资产类别决定公式。那里的 correlation 是不小于 0 且小于 1 的资产相关系数，在 systematic_factor() 中须大于 0； turnover 和 maturity 采用规则中的单位，例如百万欧元和年。

  • 在各行是分组的地方， event 是每组的事件数，例如 fit_grade_pd() 和 most_prudent_pd() （二者把它与 total 一起传入），以及各表中的 event 列。在 survival_table() 中，它则是每个账户的 0/1 标志，与之并列的 competing 是因其他原因（例如提前还款）退出的标志，二者在同一行上不会都为 1。 duration 是账户违约、退出或最后一次被观测的期数，为正整数； entry 是账户开始被观测之前经过的期数。

  • 对单个变量的函数， special 是特殊值的列表；对 fit_spec() 、 profile_table() 和 rule_candidates() ，它是按列给出的 dict，这些函数拒绝列表。

  • 有些选项名称相近但含义不同。 category_groups() 的 min_share 是低于它即视为稀有类别的占比，而 chimerge_edges() 、 tree_edges() 、 ks_edges() 、 monotonic_edges() 、 optimal_edges() 和 variance_edges() 的 min_bin_share 以及 chimerge_groups() 的 min_group_share 设定结果中最小的分箱或分组， optimal_edges() 的 min_bin_events 则设定每箱最少的事件数和非事件数，单位是权重。 rule_candidates() 的 min_hit_rate 是一条规则至少要命中的全部行的占比。只有 monotonic_edges() 接受 max_bins=None ，此时只合并分箱直到 WOE 单调。它的 direction 取 "increasing" 、 "decreasing" 或 "auto" ，而 optimal_edges() 的 trend 像 woe_trend() 那样指定 WOE 的形状，包括 U 形， variance_edges() 的 trend 则以同样的方式指定平均响应的形状。 unseen 说明如何处理表中没有的分组，默认为 "raise" ；而 unseen_points 是一个分数值或 None。 method 在 bin_edges() 、 fit_spec() 和 rule_candidates() 中指分箱方法，在 correlation_filter() 中指相关系数，在 ahp_weights() 中指权重的估计方法。 rate 在 expected_credit_loss() 中是每期的利率，在 workout_lgd() 中是年利率，可以所有贷款共用一个，也可以每笔贷款一个。

  • cutoff_table() 的 loss 和 revenue 是每个申请人的金额，须有限且非负，并像目标变量一样匹配；截断点的 profit 是其收益减去损失，因此资金成本、获客成本等费用应计入 loss 。 expected_maximum_profit() 的 no_loss_share 、 full_loss_share 和 roi 则描述一个资产组合：违约毫无损失的概率、违约损失全部贷款的概率，以及以放款金额的比例表示的好贷款回报。

  • 可能有两种理解的参考对象会分成两个参数。 kivi.monitoring 的函数要么接收 reference_period （期间参数中的一个标签），要么接收 reference_score 或 reference_groups 中的基准样本；两者必须恰好给出一个，否则引发错误。

  • 数据以及函数要应用的拟合结果（例如 cut() 的边界或 woe_transform() 的表）是位置参数。其后的所有选项都仅限关键字。 bin_edges() 的箱数是唯一也可以按位置传入的选项：

>>> from kivi.binning import bin_edges
>>> bin_edges([1, 2, 3, 4], 2)
array([-inf,  2.5,  inf])
>>> bin_edges([1, 2, 3, 4], 2, method="uniform")
array([-inf,  2.5,  inf])
>>> bin_edges([1, 2, 3, 4], 2, "uniform")
Traceback (most recent call last):
    ...
TypeError: bin_edges() takes from 1 to 2 positional arguments but 3 were given

输入与结果#

  • 一维输入是类数组（array_like）：列表、NumPy 数组或 pandas Series。同时处理多列的函数，例如 stepwise() 或 fit_spec() ，接收 DataFrame。

  • 分箱函数用 pandas.to_numeric 读取 values ，因此数字字符串和布尔值在那里都算作数值。特殊值不能是布尔值，因为 True == 1 ；而 fit_spec() 把布尔列当作类别列分组，而不是对其分箱。

  • 日期（例如 delinquency_panel() 的到期日和还款日期、 workout_lgd() 的违约日期和现金流日期，以及 make_transactions() 的申请日期）用 pandas.to_datetime 读取，可以是日期时间，也可以是字符串。数字会引发错误，而不会被当作自 1970 年起的纳秒数读取；一天中的时间被忽略；带时区的日期保留其当地日期。 workout_lgd() 和 make_transactions() 还拒绝 Period，可以用 .dt.to_timestamp() 转换。

  • kivi.features 的时间列要求更严格：它们必须已经是日期时间类型，字符串会引发错误并提示使用 pandas.to_datetime ，因为解析大型事件表中的字符串很慢，其格式也可能有歧义。它们保留一天中的时间。事件和观察的时间要么都不带时区，要么在同一个时区（按名称比较），其他组合都会引发错误；有时区时，窗口边界按当地日历计算，事件按时刻比较。 panel_features() 的 month 可以是月度 Period 或日期时间，月份和观察时间各按自己的日历取月，因此带时区的月份和带时区的观察时间必须在同一个时区。

  • 每个输入值对应一个结果值时，结果的形状与输入相同。传入 Series 得到索引和名称都相同的 Series，传入其他类数组得到 NumPy 数组，传入单个数得到 float。 cut() 和 assign_grades() 返回的是分组，因此输入不是 Series 时，它们返回 pandas.Categorical ：

>>> import pandas as pd
>>> from kivi.calibration import prior_correction
>>> rates = dict(sample_rate=0.5, population_rate=0.02)
>>> prior_correction([0.5, 0.2], **rates).round(4)
array([0.02  , 0.0051])
>>> prior_correction(pd.Series([0.5, 0.2], index=["a", "b"], name="pd"), **rates).round(4)
a    0.0200
b    0.0051
Name: pd, dtype: float64
>>> round(prior_correction(0.5, **rates), 4)
0.02

  • Series 结果采用第一个数据参数的名称， pd_to_score() 、 cut() 和 woe_transform() 的结果都是如此，因此由名为 pd 的 Series 算出的评分也名为 pd 。表示新量的结果以该量命名： woe() 把结果命名为 woe ， expected_loss() 命名为 expected_loss ， significant_increase() 命名为 significant_increase ， assign_stages() 命名为 stage ， reweighting() 、 ahp_weights() 和 combine_weights() 命名为 weight ， asset_correlation() 命名为 correlation ， capital_requirement() 命名为 capital_requirement ， conditional_pd() 命名为 conditional_pd ， systematic_factor() 命名为 factor ， most_prudent_pd() 命名为 most_prudent_pd ， conversion_factor() 命名为 ccf 。 kivi.capital 中逐值计算的函数会把各输入相互广播，因此一次调用就能覆盖一个组合：每笔敞口有自己的 PD、LGD 和期限，资产类别则只有一个。

  • 有些输入即使只有一个敞口也必须是一维的。 significant_increase() 和 assign_stages() 对单个数值会引发错误，而 expected_credit_loss() 要求每个账户一行，因此请把 convert_pd() 返回的单条曲线以 curve[None, :] 传入。

  • 描述同一批观测的 Series，例如数据、目标变量、概率和权重，必须具有完全相同的索引；它们不会被对齐。这些输入的其他任何组合都按位置对应。描述其他观测的输入，例如 psi_table() 的两个样本、 parceling() 的拒绝申请人或 delinquency_panel() 的还款记录，可以使用任意索引。每组的计数，例如 woe() 、 iv() 和 psi() 的输入，描述的是同一批分组，因此两个计数 Series 也必须具有完全相同的索引。

  • 表格是 DataFrame。由传入的分组构成的表格（例如 woe_table() 的结果）以分组标签为索引，索引名为 bin 。其他表格按其行的含义命名索引，例如 variable 、 grade 、 cutoff 、 threshold 、 statistic 、 step 、 period 、 cohort 、 start 、 state 、 stage 、 loan 、 rule 或 before ；当列也是标签时还会为列命名，例如 horizon 、 after 或 month_on_book 。 兼容性 列出了每个表格的索引和列。合计是某一列的和，例如 woe_table(groups, target)["iv"].sum() 。

  • kivi.features 的特征保留 observations 的索引及其顺序，以便拼回观察表。特征名称由参数决定：列名和 prefix 保持原样，只有 kivi 自己的部分，即聚合名和窗口，为小写，因此 Amount 和 amount 分别得到 Amount_sum_3m 和 amount_sum_3m 。

  • 具名的统计量以索引名为 statistic 的 Series 或 DataFrame 返回，例如 roc_auc_interval() 、 generalized_auc() 、 brier_decomposition() 、 concentration_test() 、 migration_bandwidth() 、 ahp_consistency() 和 expected_maximum_profit() ；或者以只用名称作索引的 Series 返回，例如 delong_test() 。供另一个函数使用的参数以元组返回，例如 platt_fit() 和 quasi_moment_fit() 为 platt_predict() 返回的斜率和截距、 isotonic_fit() 为 isotonic_predict() 返回的边界和概率，以及 vasicek_fit() 为 conditional_pd() 返回的长期 PD 和相关系数； hosmer_lemeshow() 和 spiegelhalter_test() 的统计量与 p 值也以元组返回。单个拟合参数是浮点数，例如 central_tendency_shift() 返回的 log odds 平移量，由调用者加到 PD 的 log odds 或模型的截距上。

  • kivi.plotting 的图表函数先接收 kivi 函数返回的表，再以仅限关键字的 ax 接收要绘制的 Axes；不传 ax 时在新图形上绘制。它返回 Axes，从不显示图形，也不改动 matplotlib 的全局设置。它写入的文字只有列名、参数名和数值，因此一张图适用于所有语言。

  • 函数不会修改输入。随机抽样来自以 rng 为种子的局部生成器，因此不会改变 NumPy 的全局状态，相同的种子给出相同的结果。

  • rng 接受 numpy.random.default_rng 所接受的值，例如 None、整数、 SeedSequence 或 Generator 。 Generator 会被直接使用并推进，而不是被复制，因此用同一个 Generator 的两次调用抽样结果不同，而用同一个整数的两次调用结果一致。

目标变量、评分与概率#

  • 目标变量中 1 表示事件（例如违约），0 表示非事件。其他任何标签以及缺失标签都会引发错误。 swap_set() 、 monitoring_table() 、 rule_candidates() 、 rule_table() 和 rule_set_table() 是例外：它们把缺失标签视为结果未知，例如被拒申请人的结果，或表现期尚未结束的贷款的结果，而且它们的目标变量是可选的，只有 rule_candidates() 除外，因为它要用结果来搜索。

  • response 是连续型结果，与二元的 target 相对，例如每笔违约贷款的实际 LGD 或 CCF，用于 variance_edges() 和 fractional_regression() 。它是有限实数：在 variance_edges 中可以超出 [0, 1]（例如超过 1 的 LGD），在 fractional_regression 中必须位于 [0, 1] 之内。缺失值、无穷值和布尔值都会引发错误。

  • vintage_table() 的 bad 参数是贷款在某月的状态，例如逾期 90 天，而不是一次观测的目标变量。它接受布尔值或 0 和 1，不能有缺失值； default_rate_table() 的 defaulted （贷款在某月是否处于违约）也是如此。 panel_features() 的 bad 则是有序状态列中第一个算坏的类别，默认为 "30-59" ：它和每个更差的状态都算坏。状态列必须是从最好到最差排列的有序分类，这样 current 之类的标签就不会按字母排序。

  • 在 kivi.metrics 、 kivi.monitoring 和 kivi.strategy 中，评分随事件概率升高而增大。PD 可直接传入；评分卡分值随风险升高而降低，须先取负。 kivi.strategy 的截断点通过不高于它的评分。

  • 在 kivi.scorecard 中， score 是评分卡分值，随风险升高而降低： score_to_pd() 对更高的评分给出更低的 PD。

  • platt_fit() 接受任一方向的评分，对随风险升高而降低的评分会拟合出负的斜率。 isotonic_fit() 默认评分随风险升高而增大，除非设置 increasing=False ； quasi_moment_fit() 则要求评分随风险升高而增大，例如从最好的等级起算的等级序号。

  • 在目标变量、评分和概率中，以及在 window_features() 的聚合中，True 和 False 分别计为 1 和 0，因此在那里一个标志的 sum 就是带有该标志的事件数。权重、LGD、敞口、损失、收益、 systematic_factor() 和 vasicek_fit() 的 default_rate 、 delinquency_panel() 、 workout_lgd() 和 conversion_factor() 的金额、 variance_edges() 和 fractional_regression() 的 response 、 backtest_table() 和 generalized_auc() 的 realized 和 estimated 以及比较矩阵的元素拒绝布尔值，大多数数值选项也是如此，例如 bins 、 max_bins 、 factor 和各截断点。另有六个输入拒绝布尔值，因为布尔值出现在那里更可能是错误： monitoring_table() 的 reference_score （布尔值通常是行掩码）、 transition_pd() 的 matrix 、 stage_table() 的 stage 、 assign_stages() 的 days_past_due ，以及 survival_table() 的 duration 和 entry ：

>>> import numpy as np
>>> from kivi.metrics import roc_auc
>>> roc_auc([0.1, 0.9, 0.4], [False, True, True])
1.0
>>> from kivi.strategy import expected_loss
>>> expected_loss(np.array([0.1, 0.2]), np.array([True, False]), 100.0)
Traceback (most recent call last):
    ...
ValueError: lgd must be real and numeric, got dtype bool

分组与缺失值#

对分组计数的函数，例如 woe_table() 、 psi_table() 和 calibration_table() ，按原样接收标签： pandas.cut 或 kivi.binning.cut() 的区间、字符串、数字或类别。

  • 缺失值单独成组。

  • 只出现观测到的分组。未使用的类别不会出现，权重之和为零的分组也不会出现。行集合固定的表格是例外，会保留空行： stage_table() 总有阶段 1、2 和 3， swap_set() 总有四行， kivi.monitoring 的逐期表格为类别型期间的每个类别都保留一行，使各份报告的行能够对齐。

  • 分类型分组（包括 pandas.cut 的区间）按类别顺序排列，缺失组排在最后。其他标签按首次出现的次序排列。

  • 两个样本（例如 psi_table() 中的样本）只有在具有相同的分类型 dtype 时才按类别顺序排列。否则（例如一个是有序分类型、另一个是无序分类型时），分组按首次出现的次序排列，先看基准样本，再看当前样本。

>>> from kivi.woe import woe_table
>>> woe_table(["b", "a", None, "a"], [1, 0, 1, 0])[["non_event", "event"]]
     non_event  event
bin
b            0      1
a            2      0
NaN          0      1

没有特殊值时， cut() 返回 pandas.cut 的有序分类型；给出 special 时返回无序分类型，因为特殊值排在最前，与各区间之间没有顺序。

类别按相等关系与拟合好的表格或分组匹配；表格或分组不认识的类别会引发错误，除非 unseen 指定了处理方式。 woe_transform() 、 group_categories() 和 csi_table() 遵循同一规则，最后一个通过 unseen_points 指定。 reason_codes() 匹配的是分值而不是类别，它的 unseen_points 豁免 woe_transform 赋给未见分组的分值。

拟合边界或分组的函数，例如 bin_edges() 、 chimerge_edges() 、 optimal_edges() 和 category_groups() ，在拟合时不使用缺失值；而 cut() 和 group_categories() 保持其缺失，因此计数时它们自成一组。 rule_candidates() 拟合阈值时同样不使用缺失值，缺失值也不命中它的任何规则。 variance_edges() 会把 values 的缺失值连同其响应一起排除，但遇到缺失的响应则引发错误。

进行计数、排序或拟合的函数，例如 roc_auc() 、 calibration_table() 、 cutoff_table() 和 platt_fit() ，遇到缺失的评分或概率则会引发错误，因此请在传入之前决定如何为缺失值打分。逐个转换取值的函数，例如 pd_to_score() 、 platt_predict() 和 expected_loss() ，对缺失值返回 NaN， assign_grades() 则返回缺失的等级。 kivi.lifetime 的阶段划分函数虽然逐个处理取值，但遇到缺失值会引发错误，因为缺失的 PD 或逾期天数不应决定阶段； kivi.monitoring 的函数遇到缺失的期间也会引发错误。 kivi.capital 中逐值计算的函数对缺失的 PD、LGD、违约率、因子或水平返回 NaN，但缺失的 turnover 、 maturity 或 correlation 会引发错误，因为它们决定公式。 survival_table() 、 vasicek_fit() 和 most_prudent_pd() 对输入整体计数或拟合，遇到缺失值会引发错误。 workout_lgd() 遇到缺失的贷款、日期、敞口、金额或利率会引发错误， lgd_table() 遇到缺失的 LGD、 fractional_regression() 遇到缺失的驱动因素或响应也会引发错误，而 conversion_factor() 逐个换算每个额度，返回 NaN。 delinquency_panel() 遇到缺失的贷款、日期或金额会引发错误， kivi.expert 的函数遇到缺失的比较值或权重也会引发错误。 default_rate_table() 遇到缺失的贷款、月份或 defaulted 标记会引发错误，缺失的等级则自成一行、排在最后，这符合 EBA 指引对没有评级的债务人的要求；它只在作为队列起点的行上检查 probability ，因此违约贷款的行可以留空。 central_tendency_shift() 和 quasi_moment_fit() 对输入整体拟合，遇到缺失的 PD 或评分会引发错误。 rule_table() 和 rule_set_table() 遇到规则中的缺失值会引发错误，因为数据缺失时规则是否命中本身就是规则的一部分，所以请先用 fillna 决定。验证检验同样对缺失值引发错误： backtest_table() 针对缺失的实际值或估计值， generalized_auc() 针对缺失的分段， concentration_test() 针对缺失的计数， migration_bandwidth() 和 migration_test() 针对缺失的等级或状态，因此请为离开评级等级的客户指定单独的状态。 kivi.features 的函数遇到缺失的主体、时间、月份或状态会引发错误，被聚合列中的缺失值则不参与该列的聚合，而 events 特征计入每个事件。

样本权重#

大多数对观测计数或拟合模型的函数都接受 weights ：每个观测一个有限的非负数，与数据的对应方式和目标变量相同。 psi_table() 和 csi_table() 为每个样本各接收一组权重，即 reference_weights 和 current_weights 。

weights 属于主数据，另一个样本的权重以该样本命名，例如 monitoring_table() 和 stability_table() 的 reference_weights 。 vif() 、 vif_filter() 、 correlation_filter() 、 parceling() 和 reweighting() 不接受权重，对每行一视同仁； kivi.features 的函数也是如此，每个事件只计一次。 concentration_test() 接收各等级的计数或敞口，而不是逐行数据；接收每个等级债务人数和违约数的 most_prudent_pd() ，以及每期接收一个违约率的 vasicek_fit() ，也是如此。 kivi.capital 中逐值计算的函数处理单笔敞口，不接受权重。 selection_path() 的验证样本每行只计一次。

  • 计数变为权重之和，权重为零的观测会被排除。因此整数权重与把每一行重复相应次数得到的计数相同。

  • 加权分位数采用逆累积分布（inverted CDF），因此每个内部分位数边界都是实际观测到的取值，而不加权的分位数会在观测之间插值。因此加权边界只在不需要插值时与重复行的结果一致，权重全为 1 也不等同于不加权。

  • smoothing 以权重为单位替换空单元格，不会随权重缩放。

  • logistic_regression() 、 stepwise() 、 selection_path() 、 roc_auc_interval() 、 delong_test() 、 generalized_auc() 、 spiegelhalter_test() 、 backtest_table() 和 migration_test() 把权重视为频数权重，因此它们的标准误把权重总和当作观测数。 fractional_regression() 也是如此， lgd_table() 用频数权重平均 LGD，而 workout_lgd() 和 conversion_factor() 处理单笔贷款，不接受权重。用于纠正抽样的权重（例如抽样比例的倒数）会使这些标准误偏小。

  • default_rate_table() 计入每笔贷款在其起点月那一行的权重， central_tendency_shift() 和 quasi_moment_fit() 把权重视为频数权重，例如各等级的债务人数。PD 校准中的违约率和中心趋势按债务人计数，因此权重只能用于校正抽样，不能按敞口加权（巴塞尔 CRE36.78）。

期间与阈值#

  • 类别型期间按类别顺序排列，其他期间按升序排列。期限结构或预期信用损失的第 1 期是起点之后的第一期，起点例如报告日； expected_credit_loss() 把第 \(t\) 期的违约折现 \(t\) 期。 workout_lgd() 按违约日与现金流日期之间的天数除以 365 折现每笔现金流，违约前的费用按同样方式复利。在 survival_table() 中， entry 为 \(e\) 、 duration 为 \(T\) 的账户在 \(e < t \le T\) 的各期处于风险中；在某期被删失的账户在该期仍算作处于风险中，因为删失排在该期的违约和退出之后。

  • 阈值按其所实现规则的措辞进行比较。截断点通过不高于它的评分。 significant_increase() 仅在 PD 的增幅超过阈值时才标记； assign_stages() 在逾期超过 stage_2_days 天时把贷款划入第 2 阶段，在逾期达到 stage_3_days 天及以上时划入第 3 阶段，与 IFRS 9 对 30 天和 90 天推定的表述一致。

  • delinquency_panel() 的 end 是观察的最后一个月，可以给出该月份、该月中的某个日期，或以该月结束的更长期间；每个月都在其最后一天观察，因此当天的还款计入。期款在到期日当天不算逾期，状态 90+ 从逾期 90 天开始，与 assign_stages() 用 stage_3_days 划分阶段 3 的方式相同。

  • default_rate_table() 的起点月也按同样的方式给出，可以是 Period、日期或字符串，并代表其最后一个月，因此 "2024Q2" 是 2024 年 6 月。它的队列包含该月末未处于违约的贷款，按其在该月的等级分组；之后的 horizon 个月是计入违约的窗口，因此 2025 日历年的起点月是 2024 年 12 月。

时间窗口#

  • kivi.features 的特征只使用观察时间 \(t\) 时已知的信息，因此是 时点正确 的。 window_features() 的窗口默认为 \([t - k, t)\) ，因此 \(t\) 当时及之后的事件不计入任何窗口； closed="right" 给出 \((t - k, t]\) ，适用于在其自身时间就已知的事件，例如日终余额，这只能由调用者判断。 panel_features() 的窗口包含 \(t\) 所在月之前的 \(k\) 个月，因为该月的月末状态在 \(t\) 时还不知道。

  • "3M" 按自然月计算，与 pandas.DateOffset(months=3) 相同，因此闰年 3 月 31 日之前一个月是 2 月 29 日； "90D" 按天计算。边界用大写字母书写， panel_features() 只接受月。列名中的窗口为小写，例如 3m 和 90d 。

  • windows 是列表，只有一个窗口时也是，如 windows=["3M"] 。一对单位相同、第一个更早的边界表示二者之间较早的那一期，例如 ("6M", "3M") 是 \([t - 6M, t - 3M)\) ，命名为 6m_3m 。窗口对只有作为列表中的一项才是一个窗口，如 windows=[("6M", "3M")] ； windows=("6M", "3M") 是 6m 和 3m 两个窗口。

错误与警告#

  • 无效输入会引发 ValueError ，无法拟合的模型也是如此，例如类别完全分离时会引发 kivi.selection.SeparationError 。错误信息会写明参数名；如果问题出在某个取值上，还会给出收到的值：

>>> bin_edges([1, 2, 3], bins=0)
Traceback (most recent call last):
    ...
ValueError: bins must be a positive integer, got 0
>>> roc_auc([0.1, 0.9, 0.4], [0, 1, 2])
Traceback (most recent call last):
    ...
ValueError: target must contain only 0 and 1, got 2

  • UserWarning 表示结果与请求不同，例如因取值重复而得到的箱数少于请求的箱数，并说明应如何修改。 kivi.univariate.profile_table() 则把这类重合记录在一列中，因此分析很多列时不会产生警告。

  • RuntimeWarning 表示拟合在收敛之前停止。

  • FutureWarning 预先通知公共 API 的变更。 兼容性 说明变更何时生效。

  • 消息的措辞可能在任何版本中改变，因此匹配消息的测试可能需要更新；错误和警告的类型保持不变。
