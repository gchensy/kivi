时间窗特征#

在截止于观察时间的窗口内聚合事件数据（如交易）和月度还款状态，只使用当时已知的信息。 window_features() 计算每个窗口的事件数、和、均值、极值等聚合， panel_features() 计算月度面板的坏月数、连续坏月和好月的最长月数以及最差状态， FeatureSpec 保存这两类特征的定义，可在任何样本上重新计算，并保存为带版本号的 JSON。

示例和窗口的规则见 时间窗特征 。

window_features(events, observations, *, id, ...)

在观察时间之前的窗口内聚合每个主体的事件。

panel_features(panel, observations, *, id, ...)

汇总每个主体在观察时间之前的月度还款状态。

FeatureSpec(id, observation_time[, events, ...])

时间窗特征的定义，用于以相同的方式再次计算。
kivi.features.window_features(events, observations, *, id, time, observation_time, windows=('3M', '6M', '12M'), aggregations=None, ratios=None, closed='left', prefix='')#

在观察时间之前的窗口内聚合每个主体的事件。

对 observations 的每一行，即一个主体和一个时间 \(t\) ，每个窗口收集该主体在一个截止于 \(t\) 或更早的区间内的事件，例如最近三个月 \([t - 3M, t)\) ，并聚合所选列的值：个数、和、均值、极值等。 \(t\) 当时及之后的事件从不使用，因此这些特征在观察时间已经可知。

参数:
eventspandas.DataFrame

每行一个事件，例如一笔交易，顺序任意，包含 id 和 time 列以及待聚合的列。同一主体的多个事件可以有相同的时间。

observationspandas.DataFrame

每行一个主体和观察时间，包含 id 和 observation_time 列，例如申请人及其申请日期。一个主体可以出现在多行中，例如每月一行以计算其特征随时间的变化，两行也可以完全相同。

idstr

两张表中标识主体的列，例如客户号。按相等匹配，因此 1 和 "1" 是不同的主体。

timestr

events 中记录每个事件时间的列，dtype 为 datetime。

observation_timestr

observations 中记录每个观察时间的列，dtype 为 datetime，无时区或与 time 处于同一时区。

windows序列，默认 ("3M", "6M", "12M")

观察时间之前的窗口。 "3M" 是最近三个自然月， "90D" 是最近 90 天。 ("6M", "3M") 这样的一对表示观察时间之前六个月到三个月之间的较早时期；两个边界的单位必须相同，且第一个更早。一对边界只有作为列表中的一项时才是一个窗口，如 windows=[("6M", "3M")] ； windows=("6M", "3M") 是 "6M" 和 "3M" 两个窗口。

aggregationsdict，可选

events 每一列的聚合，例如 {"amount": ["count", "sum", "max"]} ，可选 "count" 、 "sum" 、 "mean" 、 "min" 、 "max" 、 "std" 、 "nunique" 、 "first" 、 "last" 和 "days_since_last" ；见“说明”。默认只计算每个窗口的事件数。

ratiosstr 对的序列，可选

两个特征之比，每个比率是结果中的一对列名，例如 ("amount_sum_3m", "amount_sum_12m") 。近期窗口与较早窗口之比，例如 ("amount_sum_3m", "amount_sum_6m_3m") ，衡量相邻两期之间的变化。

closed{"left", "right"}，默认 "left"

"left" 把窗口取为 \([t - k, t)\) ，不含观察时间当时的事件。 "right" 把窗口取为 \((t - k, t]\) ，适用于在发生时即已可知的事件，例如日终余额；这些事件在观察时间是否已经可知，由调用者判断。窗口对也在同一侧闭合。

prefixstr，默认 ""

按原样加在每个列名前面的文字，例如取现交易特征的 "cash_" 。比率使用带前缀的列名。

返回值:
pandas.DataFrame

每行对应 observations 的一行，使用其索引并保持其行序。依次对每个窗口先给出列 {prefix}events_{window} ，再逐列、逐个聚合给出列 {prefix}{column}_{aggregation}_{window} ，例如 amount_sum_3m 或 amount_sum_6m_3m 。前缀和列名保持原样，只有 kivi 自己的部分，即聚合和窗口，用小写书写，因此 Amount 和 amount 给出不同的列。比率列在其后：分子与分母只有窗口不同时命名为 {numerator}_over_{window} ，例如 amount_sum_3m_over_12m ，否则命名为 {numerator}_over_{denominator} 。 events 、 count 和 nunique 为整数，其余列为浮点数。

异常:
ValueError

如果 events 或 observations 不是 DataFrame，如果 id 、 time 或 observation_time 不是所在表中唯一一列的名称，如果主体或时间有缺失，如果时间列不是 datetime，或者两个时间列不是同为无时区或处于同一时区。另外，如果某个窗口、聚合、比率、 closed 或 prefix 无效或重复，如果 aggregations 指定了 events 中没有的列，如果某列使用了 count 、 nunique 和 days_since_last 以外的聚合但含有非数值或无穷值，或者结果中会有两列同名，也会引发此异常。

参见

FeatureSpec

保存定义并再次计算。

kivi.univariate.profile_table

对照目标变量筛查特征。

kivi.datasets.make_applications

带日期、可作为观察表的申请样本。

说明

长度为 \(k\) 个月的窗口从观察时间之前 \(k\) 个自然月开始，按 pandas.DateOffset(months=k) 的方式计算：闰年 3 月 31 日之前一个月是 2 月 29 日，且保留一天中的时间。长度为 \(k\) 天的窗口从 \(k\) 天之前开始。有时区时，边界按当地日历计算，事件按绝对时刻比较。落在时钟拨快时跳过的那一小时内的边界移到该小时结束时，落在时钟拨回时重复的那一小时内的边界取其第一次出现。

聚合会略去所在列的缺失值； events 列统计窗口内的每个事件。在没有值的窗口中， count 、 sum 和 nunique 为 0，其余聚合为 NaN：

  • count ：值的个数；

  • sum 和 mean ：值的和与均值；

  • min 和 max ：最小值和最大值；

  • std ：样本标准差，与 pandas.Series.std 的结果相同；

  • nunique ：不同取值的个数；

  • first 和 last ：最早和最晚一个事件的值；

  • days_since_last ：从最后一个事件到观察时间的天数。

少于两个值时 std 为 NaN。 first 和 last 对同一时刻的多个事件按 events 的行序取值。 days_since_last 计入不足一天的部分，因此观察时间之前十二小时的事件距今 0.5 天；对窗口对，它仍从观察时间算起。它是经过的时间，因此有时区时，它与 "90D" 这类窗口按当地日历计的天数可能相差时钟调整的那一小时。 count 、 nunique 和 days_since_last 接受任何 dtype 的列，例如商户类型；其余聚合需要数值，布尔值按 0 和 1 计。分母为 0 或 NaN 时比率为 NaN。

observations 中没有事件的主体得到空窗口的取值， observations 中没有的主体的事件被忽略。事件只排序一次，每个窗口的边界用二分查找确定。于是计数、和、均值、第一个和最后一个值以及 days_since_last 的耗时随两张表的行数增长；每个和只累加其窗口内的值，因此之前的较大值不会把窗口内的较小值舍入掉。 min 、 max 、 std 和 nunique 会在包含某个事件的每个窗口中各访问该事件一次，因此其耗时随所有窗口的事件总数增长；这些窗口每次只展开有限的一部分，因此内存不会随之增长。

示例

>>> import pandas as pd
>>> from kivi.features import window_features
>>> events = pd.DataFrame({
...     "customer": [1, 1, 1, 2],
...     "time": pd.to_datetime(["2024-01-15", "2024-03-02", "2024-03-31", "2024-02-10"]),
...     "amount": [100.0, 40.0, 60.0, 80.0],
... })
>>> observations = pd.DataFrame({
...     "customer": [1, 2, 3],
...     "date": pd.to_datetime(["2024-03-31", "2024-03-31", "2024-03-31"]),
... })
>>> window_features(
...     events, observations, id="customer", time="time", observation_time="date",
...     windows=["1M", "3M"], aggregations={"amount": ["sum"]},
... )
   events_1m  amount_sum_1m  events_3m  amount_sum_3m
0          1           40.0          2          140.0
1          0            0.0          1           80.0
2          0            0.0          0            0.0

3 月 31 日的事件恰在观察日，因此任何窗口都不使用它；3 月 31 日之前一个月从 2 月 29 日开始。

一对边界只有作为窗口列表中的一项时才是一个窗口；单独给出时，它是两个窗口：

>>> pair = window_features(
...     events, observations, id="customer", time="time", observation_time="date",
...     windows=[("3M", "1M")],
... )
>>> pair
   events_3m_1m
0             1
1             1
2             0
>>> two = window_features(
...     events, observations, id="customer", time="time", observation_time="date",
...     windows=("3M", "1M"),
... )
>>> list(two.columns)
['events_3m', 'events_1m']
kivi.features.panel_features(panel, observations, *, id, month, status, observation_time, windows=('6M', '12M'), bad='30-59', prefix='')#

汇总每个主体在观察时间之前的月度还款状态。

对 observations 的每一行，即一个主体和一个时间 \(t\) ，每个窗口收集该主体在 \(t\) 所在月之前若干个月（例如最近六个月）的月末状态，并统计其中坏月的个数、连续坏月和连续好月的最长月数以及最差的状态。按类别的顺序，从 bad 开始的状态都算坏。 \(t\) 所在月的月末状态在 \(t\) 时尚不可知，因此该月及之后的月份从不使用。

参数:
panelpandas.DataFrame

每行一笔贷款和一个月份，包含 id 、 month 和 status 列，例如 kivi.vintage.delinquency_panel 或 kivi.datasets.make_loan_panel 的结果，顺序任意。有多笔贷款的主体在一个月中有多行，该月的状态取其中最差的一个。

observationspandas.DataFrame

每行一个主体和观察时间，包含 id 和 observation_time 列，与 window_features 相同。

idstr

两张表中标识主体的列，例如客户或贷款。按相等匹配。

monthstr

panel 中记录每个状态所属月份的列：月度 Period，或按其自身日历代表其所在月的日期时间。如果 observation_time 也有时区，有时区的日期时间必须与它处于同一时区。

statusstr

panel 中记录每个月月末状态的列，为从最好到最差排列的有序分类，例如 kivi.vintage.delinquency_panel 的 status 。

observation_timestr

observations 中记录每个观察时间的列，dtype 为 datetime。其月份按它自己的日历取，有时区时也是如此。

windows序列，默认 ("6M", "12M")

观察时间所在月之前若干个月的窗口： "6M" 是它之前的六个月。 ("12M", "6M") 这样的一对表示它之前十二个月到六个月之间的较早时期，只有作为列表中的一项时才是一个窗口，如 windows=[("12M", "6M")] 。状态按月记录，因此不允许按天的窗口。

badstr 或 int，默认 "30-59"

第一个坏状态，为 status 的类别之一。它和之后的类别都算坏，之前的类别算好。默认值是 kivi.vintage.delinquency_panel 逾期档位中的逾期 30 天。

prefixstr，默认 ""

按原样加在每个列名前面的文字，例如信用卡面板的 "card_" 。

返回值:
pandas.DataFrame

每行对应 observations 的一行，使用其索引并保持其行序。依次对每个窗口给出列 {prefix}months_{window} ，即窗口内有状态的月数， {prefix}bad_months_{window} ，即坏月数， {prefix}longest_bad_run_{window} 和 {prefix}longest_good_run_{window} ，即连续坏月和连续好月的最长月数，以及 {prefix}worst_status_{window} ，即最差的状态。然后是 {prefix}months_since_bad ，即从观察时间所在月之前最近的一个坏月到该月的月数，与窗口无关。计数为整数，最差状态的 dtype 与 status 相同，窗口内没有月份时为缺失， months_since_bad 为浮点数，此前从未变坏的主体为 NaN。前缀保持原样，窗口用小写书写，与 window_features 相同。

异常:
ValueError

如果 panel 或 observations 不是 DataFrame，如果 id 、 month 、 status 或 observation_time 不是所在表中唯一一列的名称，如果主体、月份或状态有缺失，如果 month 不是月度 Period 或日期时间，如果 status 不是有序分类或 bad 不是其类别之一，如果 observation_time 不是 datetime，或者月份和观察时间都有时区但处于不同时区。另外，如果某个窗口不是月数或重复，或者 prefix 不是字符串，也会引发此异常。

参见

window_features

事件数据的特征。

FeatureSpec

保存定义并再次计算。

kivi.vintage.delinquency_panel

分期贷款的月度面板。

说明

观察时间的月份是其所在的自然月，因此 3 月 31 日的观察使用截至 2 月末的状态。月份和观察时间各按自己的日历计算，所以两个不同的时区会引发错误：东京的 4 月 1 日在纽约仍是 3 月 31 日，那时纽约 3 月末的状态还不存在。长度为 \(k\) 个月的窗口包含该月之前的 \(k\) 个月，因此对 3 月的观察， "6M" 包含 9 月到次年 2 月。

只统计有状态的月份：窗口中早于主体第一个月、晚于其最后一笔贷款结束，或位于两笔贷款之间的月份没有状态，因此窗口的月数少于 \(k\) ，这一点由 months_{window} 反映。没有状态的月份会中断连续月数，因此一个坏月、一个缺失的月份和一个坏月是两段各一个月的连续坏月。在窗口开始之前就已开始的连续月数，只计其在窗口内的月份。

示例

>>> import pandas as pd
>>> from kivi.features import panel_features
>>> buckets = ["current", "1-29", "30-59", "60-89", "90+"]
>>> panel = pd.DataFrame({
...     "customer": ["a"] * 6 + ["b"] * 2,
...     "month": pd.PeriodIndex(
...         ["2023-10", "2023-11", "2023-12", "2024-01", "2024-02", "2024-03",
...          "2024-02", "2024-03"], freq="M",
...     ),
...     "status": pd.Categorical(
...         ["current", "1-29", "30-59", "60-89", "current", "current",
...          "current", "30-59"], categories=buckets, ordered=True,
...     ),
... })
>>> observations = pd.DataFrame({
...     "customer": ["a", "b", "c"],
...     "date": pd.to_datetime(["2024-03-15", "2024-03-15", "2024-03-15"]),
... })
>>> panel_features(
...     panel, observations, id="customer", month="month", status="status",
...     observation_time="date", windows=["3M"],
... ).T
                         0        1    2
months_3m                3        1    0
bad_months_3m            2        0    0
longest_bad_run_3m       2        0    0
longest_good_run_3m      1        1    0
worst_status_3m      60-89  current  NaN
months_since_bad       2.0      NaN  NaN

3 月之前的三个月是 12 月到 2 月。客户 b 在 3 月逾期达到 30 天，这是观察所在的月份，不会被使用。

class kivi.features.FeatureSpec(id, observation_time, events=(), ratios=(), panel=(), kivi_version=None)#

时间窗特征的定义，用于以相同的方式再次计算。

特征方案记录标识主体的列和观察时间的列，以及时间窗特征组和面板特征组。时间窗特征组包含一次 window_features 调用的参数：它读取的事件表、时间列、窗口、聚合、窗口闭合的一侧以及列名的前缀。读取筛选后事件的组，例如只读取取现交易的组，使用自己的表和前缀。面板特征组以同样的方式包含一次 panel_features 调用的参数。 compute 计算任何样本的特征， to_json 和 from_json 保存和加载这些定义。方案不从数据拟合任何东西，因此可以手工编写。

特征方案不可变：它的各组是只读映射，列表以 tuple 表示。要修改某个字段，请使用 dataclasses.replace ，它会重新验证结果。

参数:
idstr

观察表和每张事件表中标识主体的列；所有组共用这一列。

observation_timestr

观察表中记录观察时间的列。

eventsdict 序列，默认 ()

每个时间窗特征组一个 dict，键为 time （必需）、 windows 、 aggregations 、 closed 和 prefix ，其含义和默认值与 window_features 的同名参数相同，以及 table ，即该组读取的事件表的名称，默认为 "events" 。

ratiosstr 对的序列，默认 ()

任意组中两个特征之比，按列名指定，与 window_features 相同。

paneldict 序列，默认 ()

每个面板特征组一个 dict，键为 month 和 status （均必需）、 windows 、 bad 和 prefix ，其含义和默认值与 panel_features 的同名参数相同，以及 table ，即该组读取的面板的名称，默认为 "panel" 。方案至少需要一个组，可以是任一种。

kivi_versionstr，可选

写出该特征方案的 kivi 版本。默认或为 None 时取已安装的版本。

属性:
FORMAT_VERSIONint

to_json 写出的 JSON 格式的版本，也是 from_json 能读取的最新版本。

异常:
ValueError

如果 id 或 observation_time 不是字符串，如果 events 或 panel 不是由有效条目组成的 dict 列表或两者都为空，如果各组中有两个特征同名，如果某个比率无效或用到了状态，或者 kivi_version 不是字符串。每个条目的检查与 window_features 和 panel_features 的参数相同。

参见

window_features

直接计算一组事件特征。

panel_features

直接计算一组面板特征。

kivi.spec.BinningSpec

特征的分箱，以同样的方式保存。

说明

当 to_json 为两个特征方案给出相同的文本时，二者相等；文本中包含 kivi_version 。

示例

>>> import pandas as pd
>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(
...     id="customer",
...     observation_time="date",
...     events=[{"time": "time", "windows": ["1M", "3M"], "aggregations": {"amount": ["sum"]}}],
...     ratios=[("amount_sum_1m", "amount_sum_3m")],
... )
>>> spec
FeatureSpec(columns=['events_1m', 'amount_sum_1m', 'events_3m', 'amount_sum_3m',
                     'amount_sum_1m_over_3m'])
>>> events = pd.DataFrame({
...     "customer": [1, 1, 2],
...     "time": pd.to_datetime(["2024-01-15", "2024-03-02", "2024-02-10"]),
...     "amount": [100.0, 40.0, 80.0],
... })
>>> observations = pd.DataFrame({
...     "customer": [1, 2],
...     "date": pd.to_datetime(["2024-03-31", "2024-03-31"]),
... })
>>> spec.compute(observations, events=events)
   events_1m  amount_sum_1m  events_3m  amount_sum_3m  amount_sum_1m_over_3m
0          1           40.0          2          140.0               0.285714
1          0            0.0          1           80.0               0.000000
property columns#

compute 返回的列的名称，按其顺序排列。

各组的时间窗特征按组的顺序排列，然后是面板特征，比率排在最后，因此在读取任何数据之前，就可以用这些名称选择或检查结果的列。

参见

compute

计算这些列。

示例

>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(
...     id="customer",
...     observation_time="date",
...     events=[
...         {"time": "time", "windows": ["3M"], "aggregations": {"amount": ["sum"]}},
...         {"table": "cash", "time": "time", "windows": ["3M"], "prefix": "cash_"},
...     ],
... )

Index(['events_3m', 'amount_sum_3m', 'cash_events_3m'], dtype='object')
compute(observations, *, events=None, panel=None)#

计算每个观察的特征。

每个时间窗特征组给出 window_features 按其定义和事件表给出的列（不含比率），每个面板特征组给出 panel_features 按其定义和面板给出的列。随后是方案中的比率。

参数:
observationspandas.DataFrame

每行一个主体和观察时间，包含方案的 id 和 observation_time 列。

eventspandas.DataFrame 或由 pandas.DataFrame 组成的 dict，可选

事件表，或由每个时间窗特征组的 table 名称到其事件表的 dict。这些组都读取同一张表时，可以只传一张表。方案有时间窗特征组时必需，否则为 None。

panelpandas.DataFrame 或由 pandas.DataFrame 组成的 dict，可选

月度面板，或由每个面板特征组的 table 名称到其面板的 dict，规则相同。

返回值:
pandas.DataFrame

columns 中的列，每行对应 observations 的一行，使用其索引并保持其行序。

异常:
ValueError

如果 events 或 panel 既不是 DataFrame，也不是为各组的每张表各提供一项的 DataFrame dict，或者在没有读取它的组时被传入，或者出于 window_features 和 panel_features 列出的原因。

参见

window_features

一组事件特征。

panel_features

一组面板特征。

columns

列的名称。

示例

>>> import pandas as pd
>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(
...     id="customer",
...     observation_time="date",
...     events=[
...         {"time": "time", "windows": ["3M"], "aggregations": {"amount": ["sum"]}},
...         {"table": "cash", "time": "time", "windows": ["3M"],
...          "aggregations": {"amount": ["sum"]}, "prefix": "cash_"},
...     ],
...     ratios=[("cash_amount_sum_3m", "amount_sum_3m")],
... )
>>> events = pd.DataFrame({
...     "customer": [1, 1, 1],
...     "time": pd.to_datetime(["2024-01-15", "2024-02-03", "2024-03-02"]),
...     "kind": ["purchase", "cash", "purchase"],
...     "amount": [100.0, 60.0, 40.0],
... })
>>> observations = pd.DataFrame({"customer": [1], "date": pd.to_datetime(["2024-03-31"])})
>>> tables = {"events": events, "cash": events[events["kind"] == "cash"]}
>>> spec.compute(observations, events=tables).T
                                        0
events_3m                             3.0
amount_sum_3m                       200.0
cash_events_3m                        1.0
cash_amount_sum_3m                   60.0
cash_amount_sum_3m_over_amount_sum_3m 0.3
to_dict()#

以由 JSON 类型构成的 dict 返回特征方案。

该 dict 以构造函数接受的形式包含构造函数的参数，元组写成列表，因此可以用它们重建方案。它只包含 dict、list、字符串和整数，因此 json.dumps 无需进一步转换就能写出，其键的顺序始终相同。 to_json 写出的就是这个 dict。

返回值:
dict

键 format 、 format_version 和 kivi_version ，然后是参数 id 、 observation_time 、 events 、 ratios 和 panel 。 events 的每组包含全部键： table 、 time 、 windows 、 aggregations （由每列到其聚合列表的 dict，按结果中列的顺序）、 closed 和 prefix 。 panel 的每组包含键 table 、 month 、 status 、 windows 、 bad 和 prefix 。

参见

from_dict

重建特征方案。

to_json

把该 dict 写成 JSON。

示例

>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(
...     id="customer",
...     observation_time="date",
...     events=[{"time": "time", "windows": ["3M", ("6M", "3M")]}],
... )
>>> data = spec.to_dict()
>>> list(data)
['format', 'format_version', 'kivi_version', 'id', 'observation_time', 'events', 'ratios',
 'panel']
>>> data["events"][0]
{'table': 'events', 'time': 'time', 'windows': ['3M', ['6M', '3M']], 'aggregations': {},
 'closed': 'left', 'prefix': ''}
>>> arguments = ["id", "observation_time", "events", "ratios", "panel", "kivi_version"]
>>> FeatureSpec(**{name: data[name] for name in arguments}) == spec
True
classmethod from_dict(data)#

由 to_dict 的结果重建特征方案。

构建方案之前会先检查该 dict，因此损坏或被手工改动的文件会报错并指明问题。

参数:
datamapping

符合 to_dict 格式的 dict，例如来自 json.load 。 to_dict 写出的每个键都必须存在，每组中也是如此。

返回值:
FeatureSpec

特征方案，与写出 data 的那个相等。

异常:
ValueError

如果 data 不是 kivi 特征方案、其 format_version 比当前 kivi 版本能读取的更新、缺少某个键或含有未知的键，或含有无效的值。

参见

to_dict

dict 格式。

from_json

从 JSON 文本读取特征方案。

示例

>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(id="customer", observation_time="date", events=[{"time": "time"}])
>>> FeatureSpec.from_dict(spec.to_dict()) == spec
True
to_json(*, indent=None)#

以 JSON 文本返回特征方案。

该文本就是由 json.dumps 写出的 to_dict 的 dict。同一个方案总是给出相同的文本，因此保存的方案可以相互比较，也可以纳入版本控制。非 ASCII 的名称按原样写出，因此请以 UTF-8 保存文本。

参数:
indentint，可选

嵌套值的缩进，含义与 json.dumps 相同。默认文本只有一行。

返回值:
str

JSON 文本， from_json 可将其读回为相等的特征方案。

参见

from_json

读回特征方案。

to_dict

以 dict 表示的相同内容。

示例

>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(
...     id="customer",
...     observation_time="date",
...     events=[{"time": "time", "windows": ["3M"], "aggregations": {"amount": ["sum"]}}],
... )
>>> print(spec.to_json(indent=2))
{
  "format": "kivi.FeatureSpec",
  "format_version": 1,
  "kivi_version": "...",
  "id": "customer",
  "observation_time": "date",
  "events": [
    {
      "table": "events",
      "time": "time",
      "windows": [
        "3M"
      ],
      "aggregations": {
        "amount": [
          "sum"
        ]
      },
      "closed": "left",
      "prefix": ""
    }
  ],
  "ratios": [],
  "panel": []
}

用 Path("features.json").write_text(text, encoding="utf-8") 把文本写入文件。

classmethod from_json(text)#

从 to_json 写出的 JSON 文本读取特征方案。

由更新版本的格式写出的文件会被拒绝，而不会只读取其中一部分；重复某个键的 JSON 对象也会被拒绝，否则 json.loads 只会读到其最后一个值。

参数:
textstr 或 bytes

JSON 文本，例如来自 Path(...).read_text(encoding="utf-8") 。

返回值:
FeatureSpec

特征方案，与写出 text 的那个相等。

异常:
ValueError

如果 text 既不是 str 也不是 bytes、不是有效的 JSON、某个对象重复了键，或没有描述一个有效的方案；参见 from_dict 。

参见

to_json

写出特征方案。

from_dict

由 dict 重建特征方案。

示例

>>> from kivi.features import FeatureSpec
>>> spec = FeatureSpec(id="customer", observation_time="date", events=[{"time": "time"}])
>>> FeatureSpec.from_json(spec.to_json()) == spec
True
