迁移指南#

从 0.9 迁移到 1.0#

kivi 1.0 移除了 0.9 中弃用的内容。在 0.9 上运行而不发出 FutureWarning 的代码可以不加修改地在 1.0 上运行，只有导入 Dataset 或对 Series 计数使用 woe() 结果的代码除外。要找出需要修改的调用，可以在 0.9 上把 FutureWarning 变为错误来运行代码或其测试，例如 python -W error::FutureWarning 或 pytest -W error::FutureWarning 。

0.9

1.0

woe_table 、 woe 、 iv 、 psi_table 、 psi 、 monotonic_edges 、 fit_grade_pd 、 monitoring_table 和 stability_table 中的 smoothing=True 按 1 计算，并发出 FutureWarning

引发 ValueError ，与其他所有函数一致。传入 smoothing=1 可得到 0.9 的结果，省略 smoothing 则使用默认值 0.5

woe 、 iv 和 psi 按位置匹配索引不同的两个计数 Series，并发出 FutureWarning

引发 ValueError 。请先对齐计数，例如 reference, current = reference.align(current, fill_value=0) ；只有当两者的分组顺序相同时才传入数组

woe 返回数组

当某个计数参数是 Series 时，返回具有计数索引、名为 woe 的 Series。用 .to_numpy() 取得数组，用 .iloc 按位置选取；列表和数组仍返回数组

Dataset.bank_data() 发出 FutureWarning

已移除，类 Dataset 也一并移除。 kivi.datasets.load_bank() 返回相同的数据框

isotonic_predict(score, edges, probabilities=...) 发出 FutureWarning

已移除。请传入 probability= ，或按位置传入各分段的概率

kivi 1.0 仍支持 Python 3.10、NumPy 1.24 和 pandas 2.0。从 1.0 起，kivi 遵循语义化版本：弃用的内容在下一个主版本之前仍然可用，并发出 FutureWarning 。 兼容性 说明了各个版本可能改变的内容。

下表列出取代 0.2.x 各个类的函数。1.0 已移除 Dataset.bank_data() ，其示例数据由 kivi.datasets.load_bank() 提供。标签表示客户是否认购定期存款。

分箱与 WOE#

旧版 DistanceBins 和 FrequencyBins 在同一步骤中完成分箱和统计。现在先用 bin_edges 选择 uniform 或 quantile，再用 pandas.cut 分组，最后将结果传给 woe_table。abnormal_vals 中的编码改由 special 参数指定：传给 bin_edges，并用带相同编码的 kivi.binning.cut 代替 pandas.cut。原 CategoryBins 用户可直接传入类别标签序列。

0.5.0 新增 woe_transform，取代 WOEScore。旧版 WOEScore 把原始取值与 WOE 表中的 min_bin 和 max_bin 列逐一比对。现在请改用开发样本的边界划分分组，再把分组和 woe_table 的结果一起传给 woe_transform。与 WOEScore 设置 error="error" 时一样，匹配不到任何分组的取值会引发错误；也可以传入 unseen 指定其 WOE。

0.4.0 新增 chimerge_edges 和 tree_edges，用来替代 Chi2Bins 和 TreeBins。它们是重新实现而非移植，因此边界可能不同。Chi2Bins 从 10 个等频箱开始，在 0.9 置信水平下检验，给每个期望计数加 0.5，并至少保留三个箱；最接近的写法是 chimerge_edges(values, target, alpha=0.1, initial_bins=10)。TreeBins 报告 scikit-learn 选出的中点阈值，而 tree_edges 报告每个切分点下方的最大观测值。切换之前，请在固定的基准样本上核对边界。

Chi2Bins 和 TreeBins 的 abnormal_vals 中列出的编码，对应 chimerge_edges 和 tree_edges 的 special 参数。与以前一样，这些编码连同其标签不参与拟合；把相同的编码传给 kivi.binning.cut ，即可让每个编码单独成组。

群体稳定性#

迁移 PSI.fit() 时，先用同一组基准边界划分两期样本，再调用 psi_table。新结果包含各组的真实计数和单组贡献；旧结果在 psi 列逐行重复总值。新的平滑口径会在补零后归一化。迁移历史分析时应重新核对阈值。

模型、评分卡与校准#

这些模块都是重新实现的，切换之前请先在固定的参考样本上与旧版代码的结果对比。

  • 旧版的 lift 列是累计值。在 gains_table 中， lift 是每个分数段的提升， cum_lift 才是累计提升。这些指标要求分数随风险升高，例如 PD；评分卡分值请传入 -score 。 ModelEvaluate 会用每个样本自己的最小值和最大值重新缩放分数，导致不同样本间的分数不可比；新函数直接使用传入的分数。

  • VIF 调用 statsmodels 时没有加常数项，衡量的是未中心化的 R²； vif 按教科书定义在每个辅助回归中都包含截距，因此数值会不同。 stepwise 按 p 值选择变量，默认保证所有系数为正，这正是 WOE 输入的要求。它是新功能：旧版的 StepWise 比较的是变量按固定顺序加入时的各个模型，1.4.0 起由 selection_path 完成。 logistic_regression 用 NumPy 拟合模型，不再需要 statsmodels。

  • BaseScoreAndPDO 接收的是坏好比，例如 odds=1/50 。 base_odds 是好坏比，因此应传入 base_odds=50 ；若传入 1/50 ，会在没有任何提示的情况下得到 712.9 的偏移量。旧版 PDToScore 只在其中一个分支里除以了 ln 2； pd_to_score 和 score_to_pd 互为精确的反函数。

  • get_omega 的功能由 prior_correction （校正概率）和 corrected_intercept （校正模型截距）取代。

资产组合分析与生产环境分箱#

0.6.0 版又替代了三个旧版类。它们同样是重新实现的，切换之前请先在固定的参考样本上与旧版代码的结果对比。

  • WOEBatch 一次拟合多列的 WOE， ManualBinsTool 随后手动合并分箱。 fit_spec 用为每列选定的分箱函数拟合各列，得到的 BinningSpec 把边界和 WOE 表保存为带版本号的 JSON。它不会自动重新分箱：要手动合并分箱，请在 bins 中为该列传入合并后的边界。

  • CSI 按位置把分值对应到各箱，并丢失了缺失值分组。 csi_table 按标签把分值对应到各组，保留缺失值分组；若某个出现的分组没有分值，除非用 unseen_points 给出，否则会报错。各组贡献之和等于该变量平均分值的变化。

  • VintagePd 根据还款计划和观察日期构建 vintage 表。 vintage_table 接受长格式的面板数据，每笔贷款每个账龄月一行，并由你自行定义坏账标记，例如 status == "90+" ；自 1.2.0 起， delinquency_panel 可根据还款计划和还款记录构建这样的面板。传入 weights=amount 即可得到 VintagePd 按金额加权的比率。批次尚未达到的账龄月为 NaN 而不是 0。

主标尺、变量概况与策略#

0.7.0 版替代了旧版的主标尺和变量概况。切换之前请先在固定的参考样本上与旧版代码的结果对比。

  • MasterScale.fit_grade_df 和 confirm_master_scale 改为 fit_grade_pd 和 master_scale 。 fit_grade_pd 以各等级的观测数为权重，用最小二乘拟合违约率的对数，而旧版的拟合给每个等级相同的权重；各等级规模相同时两者一致。没有违约的等级以半个违约参与拟合，而不是取零的对数。等级之间的边界是相邻 PD 的几何平均；传入 boundary="arithmetic" 可得到旧版标尺的中点。

  • PDToRant(pd, ranking) 改为 assign_grades(probability, scale) 。旧版函数把恰好落在边界上的 PD 归入边界之上的等级； assign_grades 则把它归入边界之下的等级，因为 pandas.cut 的区间是右闭的。它返回由等级标签构成的有序分类，而不是等级编号。

  • FeatureEvaluate(df, target_name).stats() 改为 profile_table(frame.drop(columns=target_name), frame[target_name]) 。各列沿用 kivi 的命名，例如 missing_share 、 missing_event_rate 和 non_missing_lift ；目标变量中没有事件时会报错，而旧版的提升度为 -9999。取值本身带符号的 Gini 系数取代了单变量逻辑回归的 AUC 和 KS。该表还新增了快速分箱的 IV、特殊值编码、样本权重以及 tied_bins 列。

  • 策略分析、拒绝推断和带权重的模型拟合在 0.2.x 中没有对应功能。 kivi.strategy 取代按分数段手工制作的通过率与坏账率表， kivi.reject_inference 推断被拒申请人的结果， logistic_regression 和 stepwise 则通过 weights 纳入这些申请人重新拟合。

类别分组、模型验证与监控#

0.8.0 版本对类别变量分组，新增 ROC 表和 AUC 的不确定性，并逐期监控模型。这些同样是新的实现。

  • CategoryBins 保留类别变量原有的标签。 category_groups 合并稀有类别， chimerge_groups 合并事件率相近的类别；两者都返回一个在基准样本上拟合、从类别到分组的字典， group_categories 把它应用于每个样本。分组不认识的类别会引发错误，除非 unseen 指定了它所属的分组。 fit_spec 用 "rare" 和 "chimerge" 方法对列分组，对列分组的分箱方案保存为第 2 版格式，0.7.0 及更早版本拒绝读取。

  • BinaryMetrics.roc_curve 返回 scikit-learn 的 roc_curve 在默认 drop_intermediate=True 下的点。 roc_table 为每个不同的评分各给一行，与 drop_intermediate=False 时的 roc_curve 相同，并包含累计计数、两个比率和精确率。它的 precision 和 true_positive_rate 列就是各阈值下的精确率和召回率，因此它也给出精确率-召回率曲线，1.4.0 起可用 precision_recall_chart 绘制。 roc_auc_interval 补充了 AUC 和 Gini 的 DeLong 标准误与区间， delong_test 比较同一样本上两个评分的 AUC；旧版代码两者都没有。

  • ScoreEvaluate.score_psi 和 add_psi 比较的是两张提升表的分段合计。 monitoring_table 在只拟合一次的评分段上把每一期与同一个基准样本比较，补充了每期的已知结果、AUC、Gini 和 KS，并且结果未知的观测只计入样本量。 stability_table 给出每个变量在每一期的 PSI。

  • 存续期 PD 期限结构、IFRS 9 预期信用损失和阶段划分在 0.2.x 中没有对应功能；见 kivi.lifetime 。

图表、分类指标与变量统计量#

1.1.0 版开始绘制图表，并新增分类器的度量指标和更多的变量概况统计量。

  • plot_bin 和 DefaultAnalysis 根据原始数据绘制变量的分箱， Calibration.CalibrationCurve 绘制预测违约率与实际违约率的对比， BinaryMetrics.plot_roc 和 plot_ks 绘制 ROC 和 KS 曲线， diagonal_corr 和 structure_corr 绘制相关性热力图。 kivi.plotting 的函数改为绘制 kivi 返回的表： woe_chart 绘制 woe_table ， calibration_chart 绘制 calibration_table ， roc_chart 和 gains_chart 绘制带 KS 的 roc_table 和 gains_table ，因此 plot_ks 对应默认 ks=True 的 gains_chart ； correlation_chart 绘制 X.corr() 之类的相关系数矩阵。它们返回 matplotlib 的 Axes，而不是保存图片文件，并且需要 matplotlib，可用 pip install "kivi[plot]" 安装。

  • BinaryMetrics 的 F1 分数和混淆矩阵评判的是调用者已经预测好的标签。 confusion_table(score, target, cutoffs=...) 改为接收评分和 cutoff_table 的截断点：评分高于截断点即被拒绝，被拒绝的事件即为真阳性。把已预测的标签当作评分并传入 cutoffs=[0] ，即可得到旧版的计数。没有任何申请被拒绝时，精确率为 NaN，而旧代码给出 0 并发出警告；表中也没有 lift 列，可用 precision 除以事件率得到。

  • FeatureEvaluate 的偏度、峰度和变异系数就是 profile_table 的 skewness 、 kurtosis 和 cv 列。均值为 0 时 cv 为 NaN，而旧代码给出 -9999。 ks 是变量取值本身的 KS 统计量，即旧版 ks_test 用 SciPy 算出的统计量，但不含其 p 值。 chi2_p_value 检验快速分箱的分组与目标变量是否独立，而旧版的卡方检验是 scikit-learn 对原始取值做的 chi2 ，因此两者的 p 值不同。

  • Corr.spearmanr 给出每两列之间的 Spearman 相关系数。 correlation_filter(X, method="spearman") 在 Spearman 相关系数过高的每一对变量中剔除一个； X.corr(method="spearman") 给出相关系数矩阵本身。

逾期面板、KS 分箱与专家权重#

1.2.0 版根据还款计划构建逾期面板，新增 Best-KS 分箱，并为专家评分卡确定各因子的权重。它们同样是重新实现的，切换之前请先在固定的参考样本上与旧版代码的结果对比。

  • PortfolioAnalysis.Vintage 和 VintagePd 在每个月末观察日，根据还款计划推算每笔贷款的逾期情况。 delinquency_panel(loan, due_date, amount_due, payment_loan, payment_date, payment_amount, end=...) 根据还款计划和实际发生的还款构建这样的面板， vintage_table 再把它转换为 vintage 曲线。规则与旧版代码有以下不同：

    • 旧版的还款计划每期一行，带有该期自己的还款日期和剩余金额，也就是说源系统已经分配好了还款。 delinquency_panel 则把还款先分配给最早一期未还清的期款。

    • 旧版代码只在某期利息未还时才把该期算作未还，因此仅有本金未还不会使贷款逾期。 delinquency_panel 按全部应还金额计算，允许 tolerance 以内的差额。

    • 对于没有未还款项的贷款，旧版代码取其最近一期从到期日到还款日期的天数，因此最近一期还晚了的贷款在补齐之后仍保留这些天数。 delinquency_panel 给这样的贷款记 0 天。

    • 如果一笔贷款首期已还而之后某期未还， VintagePd 会在该次观察中将其排除，而 Spark 版的 Vintage 保留其最早一期未还的期款。 delinquency_panel 从首个到期月份起保留每笔贷款，直到其还清为止。

    • 旧版的档位为 M0 = 0、M1 = 1–30、M2 = 31–60、M3 = 61–90，M4+ 为超过 90 天。 status 的档位为 current 、 1-29 、 30-59 、 60-89 和 90+ （90 天及以上），因此恰好逾期 30、60 或 90 天的贷款会落入后一档。旧版的 M4+ 请用 days_past_due > 90 。

    • 旧版的批次是放款日期 loan_date 所在的月份。把放款日期传给 origination 即可得到相同的批次。此时 month_on_book 从放款月份起计月数，在放款月末为 0，因此比旧版的 book_month 小 1：后者把从放款月份第一天到观察日期的月数四舍五入；如需旧版的编号，请加 1。不传 origination 时， cohort 是首个到期日前一个月， month_on_book 在首个到期月份为 1，只有当首期期款在放款一个月后到期时，它才是从放款月份起计的。

    • 旧版的剩余本金只扣除在观察日期之前到期的各期已还的本金。 balance 计入月末之前的所有还款，包括提前还的款项。

    • 旧版代码从 observe_date 起，在 observe_period 个月末观察每笔贷款。 delinquency_panel 从首个到期日所在的月份起到 end 为止观察每笔贷款，并在其还清的那个月末之后将其移出面板。

    • VintagePd 在每个观察日期报告 M4+ 贷款的剩余本金占该批次放款金额的比例。这是一个时点比率，贷款恢复正常或还清时会下降。 vintage_table 统计曾经为坏的贷款，按笔数或按放款金额等权重计算。如需旧版的比率，请按批次和账龄对 days_past_due > 90 的 balance 求和，再除以放款金额。

  • ks_edges 替代 KSBins 。它是重新实现的，因此边界可能不同。 KSBins 总是切分最大的箱，而 ks_edges 切分其切分点能把最多的事件与非事件对分开的箱，并在没有任何箱存在能区分两类的允许切分点时停止。 KSBins 则在最大的箱没有允许的切分点时报错，例如该箱全是 pdays == -1 这样的特殊编码，或只含一类样本。 min_sample_rate 计入所有行，包括缺失值和 abnormal_vals ，而 min_bin_share 只计入参与拟合的取值，并按权重计算； weight 不影响 KSBins 的切分点，而 ks_edges 的切分点使用权重之和。两者都把每条边界放在其左侧箱的最大值处，并在相同时取最小的值。 abnormal_vals 中列出的编码改用 special 参数传入，与 tree_edges 相同；当 method 为 "ks" 时， fit_spec 用 ks_edges 拟合该列。

  • AHP 类接受一个包含 group 、 experimental 、 control 和 value 列的长格式数据框，按比较矩阵各行的几何平均数为每组确定权重，并以这些权重下 \((A w)_i / w_i\) 的均值估计主特征值。对单个比较矩阵， ahp_weights(matrix, method="geometric") 给出相同的权重， ahp_consistency 给出 CI 和 CR。kivi 默认使用精确的主特征向量。因子不超过三个时，它给出的权重、特征值和 CR 与旧版的估计相同；从四个因子起，判断不一致时两者略有差异。

  • weight() 返回一个数据框，其中 dst 列是因子， geo_mean 列是该行的几何平均数， group_weight 列是其在组内的权重；各组按排序后的顺序依次排列，没有组列。 group_ci 和 group_cr 保存每组的 CI 和 CR。请分别为每组确定权重，再把结果合并，如下例所示；如有需要， np.exp(np.log(matrix).mean(axis=1)) 给出 geo_mean ， combine_weights 则把各组及其因子的权重相乘得到全局权重。

  • 旧版的随机一致性指标在 3 至 11、13 和 15 个因子时相同，但 12 个和 14 个因子时为 1.54 和 1.58，而 ahp_consistency 使用 Tone 表中的 1.53 和 1.57；旧版的表还延伸到 16 个因子的 1.60，而 ahp_consistency 对 16 个因子会报错。一个因子时旧版的 CI 为 NaN 并伴有 RuntimeWarning ；一个或两个因子时， ahp_consistency 的 ci 、 ri 和 cr 都返回 0。CR 超过 0.1 在两者中都不算错误：旧版类用红色记录日志， ahp_consistency 则返回该值，由读者判断。

旧版格式的长数据框（一组三个因子，另一组两个因子）变为每组一个矩阵：

>>> import numpy as np
>>> import pandas as pd
>>> from kivi.expert import ahp_consistency, ahp_weights
>>> long = pd.DataFrame(
...     {
...         "group": ["finance"] * 9 + ["market"] * 4,
...         "experimental": np.repeat(["coverage", "leverage", "margin", "position", "share"], [3, 3, 3, 2, 2]),
...         "control": ["coverage", "leverage", "margin"] * 3 + ["position", "share"] * 2,
...         "value": [1, 1 / 2, 3, 2, 1, 4, 1 / 3, 1 / 4, 1, 1, 3, 1 / 3, 1],
...     }
... )
>>> weights, statistics = {}, {}
>>> for name, group in long.groupby("group"):
...     matrix = group.pivot(index="experimental", columns="control", values="value")
...     weights[name] = ahp_weights(matrix, method="geometric")
...     statistics[name] = ahp_consistency(matrix)
>>> pd.concat(weights, names=["group"]).round(4)

         leverage    0.5584
         margin      0.1220
market   position    0.7500
         share       0.2500
Name: weight, dtype: float64
>>> pd.DataFrame(statistics).T[["ci", "cr"]].round(4)

finance    0.0091  0.0158

时间窗特征与还款行为特征#

1.3.0 版计算事件数据和月度还款状态的特征，即 FeatureTools 、 FeatureToolsV2 和 index/collect.py 所做的工作。它们同样是重新实现的，切换之前请先在固定样本上与旧版特征对比。

  • 旧版工具基于 Spark DataFrame 运行，并把 uuid 、 index_name 、 index_val 和 load_date 构成的长表写入 Hive 分区。 window_features() 和 panel_features() 接受 pandas DataFrame，返回每个特征一列的宽表，使用观察表的索引；需要长表时可用 DataFrame.melt 转换。 batch_derivative_index 逐日运行的回溯跑批，在 kivi 中只需一次调用，观察表中每个主体和快照日期各占一行。

  • 旧版的窗口包含快照日期。 one_batch_data 保留 months_between(now_date, load_date) （以小数表示的月数）在 0 到 month - 1 之间的行， FeatureTools 和 CollectIndex 则把快照日期所在月作为每个窗口的最后一个月。kivi 的窗口是时点正确的： window_features 默认取 \([t - k, t)\) ，不含观察时间当时的事件； closed="right" 给出 \((t - k, t]\) ，对于在当天结束时就已完整的记录，这是与旧版窗口最接近的做法。月份按自然月计算，与 pandas.DateOffset 的计法相同。 panel_features 只使用观察时间所在月之前的月份，因为该月的月末状态那时还不知道。

  • FeatureTools 先按其 agg_type 汇总每个月的金额和次数，再在每个窗口内对这些月度汇总值求和、均值、极值和标准差，因此它的 amt_max 是最大的月度汇总值。 window_features 直接聚合事件本身；若要聚合月度汇总值，请把它们作为事件传入，日期设为下月初，即它们完整之时。它的 filter_rules 变为各自带 prefix 的筛选后事件表，在 FeatureSpec 中各占一组。它对两倍长窗口、12 个月窗口和前一期窗口的比率（ div2tr 、 div1y 和 chain_rate ）对应 ratios ，例如 ("amount_sum_3m", "amount_sum_6m") 、 ("amount_sum_3m", "amount_sum_12m") ，以及使用窗口对 ("6M", "3M") 的 ("amount_sum_3m", "amount_sum_6m_3m") 。分母为 0 或缺失时比率为 NaN，而 FeatureTools 会从分母中减去 1e-6，Spark 的比率算子则返回 -9999 之类的代码。

  • FeatureTools 还统计窗口内没有还款的月数，以及有还款和无还款的最长连续月数。 panel_features 在带有序状态的月度面板上统计同样的量： bad_months_{window} 、 longest_bad_run_{window} 和 longest_good_run_{window} 。请让面板中每个主体的每个月都有一行，没有还款的月份给一个坏状态，并把该状态作为 bad 传入；在逾期面板上， bad="1-29" 让任何逾期都算坏。没有行的月份不计入任何窗口，并中断连续月数，而旧版代码把它算作没有还款的月份。

  • features_agg 文档中列出的聚合对应 kivi 的名称如下： cnt 即 count ，或计入无取值行的 events 列； avg 和 mean 即 mean ； cnt_dist 即 nunique ； stddev 和 stddev_samp 即 std ，其平方就是 variance 和 var_samp ； sum 、 min 、 max 、 first 和 last 名称不变。 sum_dist 、 skewness 、 kurtosis 、 collect_set 、 collect_list 、 approx_count_distinct 以及总体统计量 stddev_pop 和 var_pop 没有移植。特征命名为 {prefix}{column}_{aggregation}_{window} ，例如 amount_sum_3m ，而不是 ent_{column}_last_{month}_{operator} 。

  • IndexField 配置一个指标的列、算子和月数，由 CollectIndex 计算。 FeatureSpec 以 aggregations 和 windows 组成的组保存同样的内容，并保存为带版本号的 JSON，但不含数据库、表和分区的设置，因为表由调用者读写。它的 id_levels 变为每个层级一个方案，各有自己的 id 列。 CollectIndex 声明了环比和同比的步骤，但没有实现；它们就是对窗口对的比率，例如 ("amount_sum_3m", "amount_sum_6m_3m") 和 ("amount_sum_3m", "amount_sum_15m_12m") 。

变量筛选、图表与 WOE 趋势#

1.4.0 版补齐了 0.2.x 的筛选、图表和 WOE 工具中最后几项还没有替代的功能，并新增欧洲央行的验证检验，它们在 0.2.x 中没有对应。这些同样是重新实现的，切换之前请先在固定的参考样本上与旧版代码的结果对比。

  • VIF.LowVIFFeatures(df, thresh=5) 依次尝试去掉每一列，剔除去掉后其余 VIF 之和最小的那一列；只要最大 VIF 不小于 thresh 且剩余的列多于两列，就继续下去。它计算 VIF 时不含截距，这会夸大均值远离 0 的变量的 VIF；它直接从传入的数据框中删除列，并返回每一步的 VIF。 vif_filter(X, threshold=5) 在含截距的情况下剔除 VIF 最大的变量，直到没有 VIF 超过 threshold 或只剩一个变量， priority （例如 IV）在 VIF 并列时决定剔除哪一个。它不修改 X ，像 correlation_filter 一样返回保留的列； vif(X[kept]) 给出这些列的 VIF。对均值接近 0 的 WOE 值，两者的 VIF 相差不大，但两种规则仍可能剔除不同的变量。

  • StepWise(df, dependent=..., indicator="auc").forward() 并不按 p 值选择变量。它按 dependent 表中的单变量指标（例如 AUC 或 KS）给变量排序，依次用前 1 个、前 2 个、前 3 个……变量拟合逻辑回归，报告每个模型的 AUC、KS、提升度和系数符号，并在 indicator 的相对增量低于 early_stop 时停止。 selection_path(X, target, order=...) 拟合同样的嵌套模型，顺序由 order 给出，例如 profile.sort_values("iv", ascending=False).index ，并报告每一步的 auc 、 gini 、 ks 、 max_p_value 和 min_coefficient ，也可在 validation 样本上计算。它不提前停止： path["auc"].pct_change() 给出 early_stop 所比较的相对增量。 backward() 从最长的模型开始拟合同样的模型，因此请从最后一行往上读。旧版遇到无法拟合的模型时只记录日志、报告中不含指标，而 selection_path 会引发 SeparationError 并指明是哪一步。模型的提升度见其拟合概率的 gains_table 。

  • woe/utils.monotony 为传入的一列数值标注趋势。 woe_trend(table) 接收 woe_table 的结果或 BinningSpec 中的一张表，按表的顺序读取区间行的 WOE，不考虑特殊值和缺失值的行；对类别变量则会引发错误。两者的标签一一对应：

    monotony

    woe_trend

    单调上升

    "increasing"

    单调下降

    "decreasing"

    下降上升

    "u_shaped"

    上升下降

    "inverted_u"

    未知

    "irregular"

    数据不足 ，即只有一个值

    "flat"

    monotony 把相等的相邻值算作上升，因此 [0.3, 0.3, 0.1] 是 上升下降 ，全部相等的值是 单调上升 。在 woe_trend 中，WOE 的相对差不超过 \(10^{-10}\) 的相邻值既不算上升也不算下降，因此同样的值是 "decreasing" ，全部相等的值是 "flat" 。

  • BinaryMetrics.plot_score 绘制好客户和坏客户评分的直方图和核密度。 distribution_chart 对 gains_table 的每个分数段或 woe_table 的每一箱，用并排的柱形绘制其占全部非事件和占全部事件的比例； plot_ks 把评分切成 40 个等宽的分数段，而 gains_table(score, target, bins=40) 给出 40 个等频的分数段；等宽的边界，例如把 np.linspace(score.min(), score.max(), 41) 的首尾两个换成 -np.inf 和 np.inf ，给出 plot_ks 的分数段。 plot_pr 用直线连接 pr_curve 的各点，用 ROC 曲线的 AUC 标注该曲线，并画出从 (0, 1) 到 (1, 0) 的对角线。 precision_recall_chart 把 roc_table 的 precision 和 true_positive_rate 画成阶梯，其下面积就是平均精确率，并在事件率处画一条线，即随机排序评分的精确率。

未迁移的功能#

Spark、SQL、模型封装和应用代码不在范围之内，仍保留在历史版本中：包括 spark 、 index 和 FeatureToolsV2 中的 Spark 会话、分区和 Hive 写入（它们所算的特征现在由 kivi.features 基于 pandas 计算）、 Model 中的模型封装，以及 utils 中的 Excel、Markdown、日志和日期工具。以下 0.2.x 工具同样没有替代：

  • 分箱类 KmeansBins （以 k-means 聚类的边界为切点）和 PearsonBins （逐步减少分位数分箱的个数，直到分箱与坏账率的秩相关系数达到阈值）。 monotonic_edges 能达到 PearsonBins 所追求的单调 WOE， 分箱 中的监督分箱方法则替代 KmeansBins 的聚类。

  • 抽样工具 sampling 和 upsampling ， FeatureTools 中 joint_feature 的中位数交叉和缺失交叉特征、它的趋势标志和高于或低于平均值的月数、它对数据框两列求比的 ratio ，以及 Scale 的 min-max 和 z-score 缩放。请使用 pandas。时间窗特征的比率自 1.3.0 起由 window_features 的 ratios 计算。

  • FeatureToolsV2 中 index_indu_pct 和 pct_rank 的行业百分位排名。请用 pandas 在组内对特征排名，例如 features.groupby(industry).rank(pct=True) 。

  • BetaCalibration 、 BetaDistribution 和 MasterScale.cal_quantile 中基于 Beta 分布的分级、 MasterScale.plot_grade_rate 中其各等级占比的图，以及 model_score_by_weight 。 master_scale 和 woe_to_points 不依赖它们即可完成相同的步骤， calibration_chart 则比较每个等级的预测违约率与实际违约率。

  • FeatureEvaluate 的单变量逻辑回归拟合及其 KS 检验的 p 值。 profile_table 的 gini 和 ks 直接衡量变量取值对目标变量的排序能力。

  • ODDS （计算评分区段的稳定性指数）和 StatsLogit （statsmodels 逻辑回归的封装）。请使用 psi_table 和 logistic_regression 。

  • woe/utils 中的 int_score ，它把分数取整到 0 到 100 之间最接近的 5 的倍数。请用 (score / 5).round().clip(0, 20) * 5 ，它把恰好居中的值取整到偶数，而 int_score 向下取整。取整后的各项分值之和不再等于取整后的总分，因此只对总分取整。

  • StepWise.top_n_features ，它在每个维度中保留 KS 最高的变量。若 dimension 是把每个变量映射到其维度的 Series， profile.assign(dimension=dimension).sort_values("iv").groupby("dimension").tail(n) 保留 profile_table 每个维度中 IV 最高的 n 个变量，改用 sort_values("ks") 则保留 KS 最高的变量。

  • BinaryMetrics.plot_confusion_matrix ，即混淆矩阵四项计数的热力图。 confusion_table 为每个截断点返回这些计数。

  • Dataset.crime_data() （美国各州犯罪率数据，与信用风险无关），以及 MakeData （划分为训练集和测试集的 scikit-learn 分类样本）和 fake_data （对坏客户和好客户分别从不同范围抽取每一列）的合成数据。 make_applications 和 make_loan_panel 改为模拟贷款申请和贷款组合，自 1.3.0 起 make_transactions 还模拟每笔申请之前的账户交易流水，这是两个旧版生成器都没有的。
