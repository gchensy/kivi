旧版评审#

这份对 0.2.x 代码的评审指导了 0.3.0 的重写。其中的发现描述的是旧版实现；各部分的替代方式见 迁移指南 。

旧版实现中的问题#

  • 打包。0.2.8 的 wheel 将 NumPy 和 pandas 列在 all 可选依赖中。默认安装后可以导入 kivi，但加载数据和调用 WOE 都会失败。

  • 依赖。evaluate/BucketsUtils.py 在模块加载时导入 PySpark，连 pandas 版 PSI 也依赖 Spark。该文件的独立 CSI 函数引用了未定义的 self。新版指标函数只依赖 pandas 和 NumPy。

  • 数值结果。旧版 WOE 使用 if/elif 处理零频数，一次只调整一类，还沿用调整前的分母。旧版 PSI 会更改展示的计数。新版测试检查原始计数、归一化占比及手算指标。

  • 状态。Model/Tree.py 会从调用方传入的 DataFrame 中移除目标列。模拟数据生成器也会重置 NumPy 的全局随机状态。后续迁移估计器时，应保留输入并使用局部随机种子。

  • 测试。旧版评分卡与 WOE 用例打印结果表，却没有断言具体数值。迁移前应用固定样本核对分箱边界、评分方向、特殊值和总行数。

  • 项目范围。旧目录混合了建模算法、数据库、分布式计算、笔记本与部署配置。新增集成时应在可选模块内导入相应依赖，将业务 SQL 和本地配置保留在分发包之外。

落实情况#

重写从分箱、WOE 和 PSI 开始，随后重建了评分卡流程的其余部分，每一部分都在固定样本上与旧版输出或参考实现核对过。 版本说明 按版本列出了这些部分。Spark、SQL 和模型封装没有重建：它们不在范围内，保留在重写之前的仓库历史中。专家评分卡的层次分析法后来在 1.2.0 中以 kivi.expert 重建，基于 Spark 的特征工具所计算的特征则在 1.3.0 中基于 pandas 以 kivi.features 重建。
