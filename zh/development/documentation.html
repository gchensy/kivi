编写文档#

英文版和简体中文版由同一套页面和 docstring 构建。本页说明文档的组织方式和写法；每个拉取请求都要运行的检查见 开发 。

页面类型#

除首页和各部分的目录页外，每个页面都属于下列五种类型之一，类型决定了页面的内容。

类型

页面

内容

教程

快速开始部分和教程部分的各个页面，以及 风控建模流程

安装说明，以及用随包数据从头到尾完成的示例。细节链接到对应的主题指南，不在教程里重复。

主题指南

用户指南的其余页面

风控模型中的一个步骤：它衡量什么、一个示例，以及如何解读结果。 示例数据 以同样的方式介绍示例数据。

参考

API 参考的各个页面

约定 ，即所有函数共同遵守的规则； 兼容性 ，即一个版本可以改变什么； 术语表 ，即各篇指南所用的术语；以及每个公共模块一页，由模块的 docstring 生成。

版本说明

版本说明 和 迁移指南

每个版本的变化，以及如何把代码从 0.9 迁移到 1.0、把使用 0.2.x 类的代码迁移到替代接口。已发布版本的说明不再修改；当某个版本改变了迁移指南所描述的内容时，迁移指南随之修订。

如何参与 kivi 的开发。 旧版评审 记录重写之前对 0.2.x 代码的评审。

页面位置#

  • 公共模块 kivi.<module> 有一个 API 页面 docs/api/<module>.rst ，通常还有一个主题指南 docs/user_guide/<topic>.rst 。API 参考和用户指南的 toctree 按项目顺序列出各页，并以通配符结尾，所以新页面无需修改它们就会出现在末尾。集成时再把它移到应有的位置，详见下文“入口页面”。

  • 教程部分 docs/tutorial 用多个章节完整跟踪一个项目，各章节由其索引页的 toctree 按项目顺序列出。每章开头有一个折叠的 dropdown ，重复该页需要的前面各章的代码，使每页都能单独运行。只有模拟数据才能给出的结果，例如被拒绝申请人的结果，放在标题为 Simulation check 、类为 kivi-check 的 admonition 中，项目的各个步骤从不依赖它们。

  • 约定、兼容性承诺和术语表分别是 docs/api/conventions.rst 、 docs/api/compatibility.rst 和 docs/api/glossary.rst 。它们排在 API 参考的最前面，用户指南目录页链接到约定和术语表。

  • 页面名是 URL 的一部分，语言切换也会把每个页面链接到另一种语言中同名的页面。需要调整时改页面标题，不要重命名或删除页面。

  • 同一个模块的 API 页面和主题指南使用同一个标题。它的卡片和 README 中的行使用这个标题或其简称，例如 WOE 与 IV。

主题指南#

主题指南按分析的顺序组织，读者找到所需内容即可停下。各节按下表的顺序排列，表中以行内代码给出的是各节的固定标题：

节

内容

开篇，不加标题

这一步回答什么问题，在风控模型中处于什么位置，并按用户指南的顺序链接到前后步骤的指南。本页涉及的公共函数，每个都链接到其 API 条目。开篇不含示例。

Definition （定义）

指标及其公式（放在 math 块中），位于所有示例之前。定义多个指标时标题用 Definitions ；如果页面上的每个工具都在各自的小节中定义，则省略本节。

A worked example （计算示例）

读者可以手工验算的几个数值，紧接在定义之后。

正文各节

这一步的每个任务、工具或问题各占一节，按项目的顺序排列，并给出基于内置数据的示例以及如何解读其结果。正文小节的标题用名词短语，例如 Gains table ，或动名词短语，例如 Choosing a cut-off ；祈使句式的标题留给教程的步骤。正文小节可以再分子节。

Reading the result （解读结果）

页面主要结果各列的表格、指标的方向、常用阈值以及下一步要检查什么。它位于打印该结果的正文小节之后、介绍其他工具的正文小节之前。如果页面上的每个工具各自返回一张表，则由各正文小节分别说明自己的表。

Special values （特殊值）

如何把表示“不适用”的 -1 等编码传入 special ，以及它们最终落入哪个分组。

Missing values （缺失值）

缺失值如何计数、分组或被拒绝。

Sample weights （样本权重）

weights 改变什么、不改变什么，以及加权结果在哪些地方与重复行的结果不同。

Limits （局限）

方法无法说明什么，以及 kivi 没有实现什么。

Errors and warnings （错误与警告）

读者可能遇到的错误和警告，以及解决方法。

不适用的小节可以省略，但其余小节要保持顺序和标题不变，让各篇指南读起来一致。一两句话就能说明的变体可以留在它所属的正文小节中，只属于某个任务的错误也可以在该任务处展示；需要示例的变体或错误才单独成节。

小节锚点也是 URL 的一部分，README 会链接其中一些锚点。README 链接到的小节不要改标题；小节移动时要保留它的标签。

示例#

  • 示例都是 doctest，由 build 检查运行。输出必须真实：改动影响了打印出的表格时，重新运行代码并粘贴新的输出，不要手工修改数字。

  • 示例使用 示例数据 中介绍的数据，或者少量读者能手工验算的数值。随机数据由固定种子的生成器产生。

  • 每个函数都从其所在模块导入，例如 from kivi.woe import woe_table 。

  • 示例不能产生警告：doctest，或 docs/_plotting.py、docs/_diagrams.py 与 docs/_tutorial.py 中的图表和示意图函数一旦发出警告，构建就会失败。如果示例要演示某个警告，请用 warnings.catch_warnings(record=True) 捕获它并打印警告信息。

  • 同一页面的所有示例共享一个命名空间，因此后面的小节可以使用前面小节定义的名称。移动小节时，请检查每个名称在使用之前仍有定义。

图表#

图表和示意图在构建文档时绘制。 plot 指令调用一个 figure_* 函数，该函数重新计算紧挨在它上方的示例，所以两者要一起修改：

  • 图表来自 docs/_plotting.py ，以 kp.figure_*() 调用，在随包数据上绘制某个结果，例如各组的 WOE 或账龄曲线。

  • 教程的图表来自 docs/_tutorial.py ，以 kt.figure_*() 调用，先一次性重建项目的状态，再用 docs/_plotting.py 中的函数绘制。

  • 图表 （ kivi.plotting 的指南）中的图表在 plot 指令里重算其表之后直接调用公共绘图函数，因为该指南展示的正是读者自己会写的代码。

  • 示意图来自 docs/_diagrams.py ，以 kd.figure_*() 调用，展示函数如何计算结果：输入的行、调用和结果表，以及 kivi 返回的数值。主题指南把主要的计算画成示意图，紧接在计算示例之后，或放在该计算所属正文小节的第一个示例之后。

图表和示意图中的文字只使用 kivi 的列名、参数名、数据值以及由它们写成的公式，这样一张图可以同时用于两种语言。图注解释图的含义，替代文本描述图的内容，两者都会被翻译。如果绘图函数在所展示的函数之外另行计算数值，就要用该函数核对这些数值，这样函数一旦改变，构建就会失败，而不会留下过时的图。

名称与链接#

  • 参数名和列名写成行内代码，例如 special 或 event_rate 。

  • 在主题指南和教程中，kivi 的函数、类或模块在每一节第一次出现时链接到其 API 条目。使用 :func: 、 :class: 、 :exc: 、 :meth: 和 :mod: 角色及完整名称，并在前面加波浪号，例如 :func:`~kivi.woe.woe_table` ，这样只显示名称。需要用模块区分两个函数时保留模块名，例如与 pandas.cut 并列时写 :func:`kivi.binning.cut` 。同一节中后续出现的名称仍写成行内代码。

  • woe 、 iv 、 psi 、 ks 和 gini 既是函数名，也是列名。只有表示函数时才加链接。

  • 示例中的名称是代码，不加链接。

  • 链接到其他页面用 :doc: 角色，链接到其他页面的某个小节用 :ref: 角色。只有当某个链接指向一个小节时，才给它加标签。

API 参考#

  • API 参考 先列出约定、兼容性页面和术语表，再按用户指南的顺序列出各模块页面，最后以通配符收录尚未集成的页面。 api/datasets 通过通配符排在最后，从而保证通配符总能匹配到页面。

  • 模块页面依次包括：标题、 module 指令（为 :mod: 链接提供目标）以及简介。简介用一两句话说明模块的用途并链接其主要函数，再用一句话链接到对应的主题指南。之后是各条目。例如：

    Binning
=======

.. module:: kivi.binning

Fit bin edges on a reference sample and group every sample with the same edges.
:func:`~kivi.binning.bin_edges` fits them from the values alone, ...

See :doc:`/user_guide/binning` for examples and how to choose the edges.

.. autosummary::

   bin_edges
   cut

.. autofunction:: bin_edges

.. autofunction:: cut

  • 模块的 API 页面要记录模块 __all__ 中的每个名称：先列在 autosummary 表中，再按同样的顺序各自给出 autofunction 、 autoclass 、 autoexception 或 automethod 条目。某个名称没有这样的条目时， python docs/build.py 会停止。

  • docstring 遵循 numpydoc 约定，并启用全部校验项，因此缺少某个小节（例如 See Also 或 Examples）会导致构建失败。docstring 的段落和页面一样需要翻译。

  • 约定 收录所有模块共同遵守的规则，例如参数顺序和 weights 的含义。指南或 docstring 只说明本模块自己的规则，共同规则则链接到约定页面。 术语表 对每个术语只定义一次，并链接到使用它的指南。

翻译#

中文版由 docs/locale/zh_CN/LC_MESSAGES/kivi.po 生成。英文页面和公共 docstring 中的每个段落都对应该文件中的一个条目。如果有条目缺失、标记为 fuzzy 或已不再使用，python docs/build.py 会停止构建。

修改英文内容后：

  1. 运行 python docs/build.py --update-po。新字符串以空译文加入，已修改的字符串保留旧译文并标记为 fuzzy。

  2. 翻译空条目，复核 fuzzy 条目并删除其 #, fuzzy 行。

  3. 再次运行 python docs/build.py。

翻译时，行内代码、链接等行内标记的两侧要留空格或使用中文标点，否则标记无法识别。每个术语沿用翻译目录中已有的译法，让中文版保持统一的用词。

只替换标记的修改（例如把行内代码换成链接）不会使译文失效。请在第 1 步之前，把同样的修改应用到 kivi.po 的源字符串及其译文上，这样条目就不会变为 fuzzy。

入口页面#

有些页面描述整个库： README.md 和 README.zh-CN.md 、首页、用户指南目录页以及 风控建模流程 。新增模块的拉取请求不修改它们。它们在一批这样的拉取请求合并之后统一更新，而且这次更新要按库的现状重写，而不只是追加内容：

  • 首页的标题、简介和步骤；

  • 首页和用户指南目录页上的卡片，以及用户指南的页面顺序；

  • API 参考的页面顺序；

  • 新页面前后相邻的指南开篇中指向上一步和下一步的链接；

  • 新模块需要加入 术语表 的术语和 约定 的规则；

  • 两份 README 中的表格和路线图；

  • 迁移指南 中关于尚未迁移功能的所有表述。

新增模块的拉取请求要在描述中列出它所需的术语和约定，就像列出它的图表一样。

python docs/build.py 会列出 README 的 API 表格中遗漏的每个公共函数，以及每个在用户指南目录页上没有卡片、或在 README 中没有链接的用户指南页面。在这个列表清空之前， python docs/build.py --release 拒绝运行。

发布文档#

GitHub Actions 上的 Documentation 工作流会对每个拉取请求运行测试并构建两种语言的文档。在 master 分支上，它还会把 docs/_build/html 发布到 gh-pages 分支，通过 https://gchensy.github.io/kivi/ 访问。
