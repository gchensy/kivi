发布到 PyPI#

推送版本标签时，Release 工作流会把 kivi 发布到 PyPI。它使用 PyPI 可信发布（trusted publishing），因此仓库中不保存任何 API 令牌。

  1. 把 pyproject.toml 中的 version 改为新版本号，例如 0.3.1 。运行 python docs/build.py --release 0.3.1 ，它会把发布说明文件移入 版本说明 中以当天日期命名的新章节；然后翻译新章节的标题。

    如果 python docs/build.py 仍报告有入口页面需要更新，这条命令不会做任何改动，详见 编写文档 。

  2. 将改动合并到 master 分支。

  3. 在合并后的提交上打 v 加版本号的标签，并推送该标签：

    git switch master
git pull
git tag v0.3.1
git push origin v0.3.1

推送标签后上传会直接开始，没有审批环节，因此只在准备好发布时才推送标签。如果标签与版本号不一致，或者标签指向的提交不在 master 上，工作流会在上传任何内容之前停止。否则它会运行测试，构建源码包和 wheel，用 twine 检查后上传到 PyPI。上传成功后，它才会创建 GitHub release，附上安装包，并根据已合并的拉取请求生成说明。0.4.0rc1 这类版本会被标记为预发布。

仓库在三处保护这条发布路径：

  • 只有仓库管理员可以创建、移动或删除 v* 标签。

  • pypi 环境只接受来自 v* 标签的部署。

  • PyPI 只信任 gchensy/kivi 中在 pypi 环境下运行的 release.yml 工作流。

PyPI 不接受重复上传同一个版本。如果运行在上传之前失败，可以用 git push origin :refs/tags/v0.3.1 删除标签，修复问题后重新打标签。如果已经上传成功，请用新的版本号发布修复。
